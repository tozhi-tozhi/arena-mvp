# Skill: Netcode — การจัดการปิง (Co-op ออนไลน์)

วิธีใช้: แนบไฟล์นี้เมื่อทำงานเกี่ยวกับ co-op ออนไลน์ · วางที่ `docs/ai/skill_netcode_ping.md`
สถานะ: **โน้ตแนวคิด ยังไม่ได้ทำในโค้ด** (Phase 5 — ต้องทำหลังรื้อ singleton และแยกชั้น Input)

---

## 0. สถาปัตยกรรมที่เลือกไว้ (ร่าง รอยืนยัน)

- **Host-authoritative:** เครื่องของคนสร้างห้องเป็น "Host" รันบอส/ตัวแทะ/ของตก/เควสทั้งหมด
  เพื่อนส่งแค่ **Input** (ปุ่มที่กด) ไปให้ Host แล้วรับสถานะกลับมา
- ต่อกันผ่าน **WebRTC** (เช่น PeerJS ใช้ signaling ฟรี ไม่ต้องมีเซิร์ฟเวอร์เอง)
- แมพสุ่มจาก **seed** → ส่งแค่ seed ให้ทุกเครื่องสร้างแมพเอง ไม่ต้องส่งตัวแมพ
- ข้อควรระวัง: WebRTC ตรงบางเครือข่าย (เช่น เน็ตมือถือบางเจ้าที่ใช้ CGNAT) อาจต่อกันไม่ติด
  ถ้าไม่มี TURN relay → ต้องทดสอบจริงบนเน็ตมือถือก่อนสัญญากับผู้เล่น

---

## 1. Client-Side Prediction — แก้ปัญหาเดินอืด
- ปัญหา: กดเดินแล้วรอ Host ตอบกลับ → ตัวละครหน่วง
- วิธี: เครื่องผู้เล่นขยับตัวละครของตัวเอง **ทันที** พร้อมส่ง Input ไปบอก Host
- ผล: การควบคุมลื่นมือไม่ว่าปิงเท่าไร

## 2. Server Reconciliation — แก้ปัญหาเดินทะลุ/ตำแหน่งเพี้ยน
- ปัญหา: เครื่องผู้เล่นเดินล่วงหน้า อาจทะลุกำแพงหรือเพี้ยนจากตำแหน่งจริง
- วิธี: Host ส่งตำแหน่งจริงกลับมาเป็นระยะ ถ้าไม่ตรง ให้ **ดึงกลับแบบเนียน (smooth snap)** ไม่กระชาก
- เคล็ด: Input ทุกก้อนมีเลขลำดับ (seq) → เมื่อ Host ยืนยันถึง seq ไหน ให้เล่นซ้ำ Input ที่ยังไม่ยืนยัน

## 3. Interpolation — แก้ปัญหาเพื่อนเดินกระตุก/วาร์ป
- ปัญหา: ตำแหน่งเพื่อนมาเป็นก้อนเป็นพัก ๆ ถ้ากระโดดใส่ทันทีจะเห็นวาร์ป
- วิธี: แสดงเพื่อน **ช้ากว่าความจริงเล็กน้อย (ราว 2 tick)** แล้ว Lerp ระหว่างจุดเก่าไปจุดใหม่
- ใช้กับ: ผู้เล่นคนอื่น และบอส/ตัวแทะบนเครื่องที่ไม่ใช่ Host

## 4. Lag Compensation / Hit Rewind — แก้ปัญหาตีบอสไม่โดน
- ปัญหา: ผู้เล่นปิง 100ms เห็นว่าฟันโดน แต่ในมุมมอง Host บอสขยับหนีไปแล้ว
- วิธี: Host ย้อนดูตำแหน่งบอสเมื่อ "ปิงของผู้เล่นคนนั้น" มาแล้วตัดสินว่าโดนหรือไม่
- **ลำดับความสำคัญต่ำ (ทำทีหลัง):** เกมนี้เป็น PvE ร่วมมือ ไม่ใช่ PvP แข่งความเร็ว
  เริ่มแบบง่ายก่อน: ให้ Host ตัดสินจากตำแหน่งปัจจุบัน + ขยายพื้นที่โดนตีเล็กน้อย แล้วค่อยเพิ่ม rewind ถ้าผู้เล่นบ่นจริง

## 5. Tick Rate + Snapshot — คุมแบนด์วิดท์
- ส่งสถานะเป็นรอบ ไม่ใช่ทุกเฟรม: เริ่มที่ **20 ครั้ง/วินาที** (ปรับได้ถึง 30)
- มัดสถานะทุกคนเป็น Snapshot ก้อนเดียวต่อรอบ
- ส่งเฉพาะที่เปลี่ยน/จำเป็น: ตำแหน่ง, ความเร็ว, ทิศหัน, สถานะอนิเมชัน, HP — ไม่ส่งภาพหรือเอฟเฟกต์

---

## 6. ลำดับทำตอนเริ่มจริง (MVP → เต็ม)

| ขั้น | ทำอะไร | หมายเหตุ |
|---|---|---|
| 1 | Tick Rate + Snapshot (ข้อ 5) | พื้นฐานของทุกอย่าง |
| 2 | Prediction (ข้อ 1) + Interpolation (ข้อ 3) | เพียงพอให้ "เล่นกับเพื่อนได้ลื่น" |
| 3 | Reconciliation (ข้อ 2) | เมื่อเริ่มเห็นตำแหน่งเพี้ยน/ทะลุ |
| 4 | Lag Compensation (ข้อ 4) | เฉพาะถ้าผู้เล่นรู้สึกตีไม่โดนบ่อย |

## 7. นโยบายปิง (ค่าเริ่มต้นสำหรับจูน — ยังไม่ได้ทดสอบ)

| ปิง | พฤติกรรม |
|---|---|
| ต่ำกว่า ~80ms | เล่นปกติ |
| ~80–150ms | เล่นได้ด้วย Prediction + Interpolation |
| มากกว่า ~150ms | โชว์ไอคอนเตือนปิงสูงที่ HUD |
| มากกว่า ~250ms หรือหลุดต่อเนื่อง | เสนอให้ผู้เล่นออก/ให้ Host ตัดสินว่าจะรอหรือไม่ |

- โชว์ปิงที่ HUD เสมอใน co-op
- ให้ Host เป็นเครื่องที่เน็ตดีที่สุด (ทดสอบปิงก่อนเริ่มห้อง)

## 8. สิ่งที่ต้องรื้อในโค้ดปัจจุบันก่อน (ยังไม่ทำ)
- `pouch`, `huntSession`, `loadout` เป็น singleton ระดับโลก → ต้องเป็นของแต่ละผู้เล่น
- `PlayerActor` ผูกกับผู้เล่นคนเดียว · บอส/`CombatTarget` สมมติว่ามีผู้เล่นเดียว
- ชั้น Input ต้องแยกออกมาเป็นข้อมูล (ดู `InputSource` ในแผนควบคุมมือถือ) เพราะ Prediction/ส่งผ่านเน็ตต้องใช้ Input เป็นก้อนข้อมูล
- ห้ามแก้ Gameplay กับ Art พร้อมกัน — รื้อ singleton เป็นรอบแยกที่เกมเดิมเล่นได้เหมือนเดิมทุกอย่าง

## 9. ข้อสรุปจากแหล่งที่มา
เกม Action Co-op แบบร่วมมือ ไม่ต้องคมระดับ FPS แข่งขัน → Prediction + Interpolation + Tick Rate ที่เหมาะสมก็พอให้เล่นกับเพื่อนสนุก
