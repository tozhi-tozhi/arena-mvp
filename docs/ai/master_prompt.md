## ⚠️ กฎเหล็กอันดับหนึ่ง — บทเรียนราคาแพง 4 ครั้ง (Session 5 · 7 · 14 · 16)

**Session 5:** AI อ่านแพ็กเก่า แล้วสรุปว่า "มินิแมปยังไม่มี · ฐานยังไม่ได้ทำ" ทั้งที่ทำเสร็จแล้ว ผู้พัฒนาต้องแก้ 3 รอบ

**Session 7:** ผู้พัฒนาส่งแพ็กที่ **ยังเป็นก่อนแพตช์สเกลเลือด** (ยังเห็น `maxHP: 6` · `hp: 80` · `DEPTH_TIERS` 1/3/6 · `PlayerHUD` วาดเป็นช่อง) แต่ในแชตยืนยันแล้วว่าวางแพตช์ + `tsc` ผ่าน + เจอบั๊กที่เกิดจากสเกลใหม่เท่านั้น → **ของใหม่กว่าชนะเสมอ ห้ามยึดแพ็กเก่าแล้วเขียนโค้ดทับของที่ทำแล้ว**

**Session 14 (แพงที่สุด — แก้จอทั้งวัน):** AI ส่งแพตช์แก้กล้อง/UI เกิน 8 รอบโดยเดาสาเหตุผิดทุกครั้ง ผู้พัฒนาต้องวางแล้วพังซ้ำ ๆ

ลำดับความผิดพลาดจริงใน S14:
1. เปลี่ยน `width/height` ใน `main.ts` ตามขนาดจอ → พื้นที่ตรรกะเปลี่ยน → UI เพี้ยนทั้งกระดาน (แต่ภาพคมจริง)
2. เดาว่า `makeVignette` ไม่มี `setScrollFactor(0)` ทั้งที่มีครบ → เสียเวลาเปล่า
3. สั่งให้พิมพ์ `game.…` ใน Console ทั้งที่ `const game` อยู่ใน ES module ไม่โผล่เป็น global → `not defined` ทุกคำสั่ง
4. ชดเชย scroll ด้วยเครื่องหมาย **บวก** แทนลบ → เลื่อนหนีไปไกลกว่าเดิม (`เห็น 317` → `เห็น 634`)
5. ลืมว่า **วัตถุ `scrollFactor(0)` ไม่รับ scroll ของกล้อง** → การชดเชย scroll ไม่มีผลกับ HUD เลย (แต่ได้ผลกับปุ่มสัมผัสที่ไม่ได้ตั้ง scrollFactor)
6. ส่งบล็อกอัปเดต master prompt แค่ 200 บรรทัด ทั้งที่เอกสารจริง 1,100 บรรทัด → ผู้พัฒนาต้องแปะฉบับเต็มกลับมาให้

**สิ่งที่ปิดงานได้จริง:** เพิ่มบรรทัดวินิจฉัยในเกม (อ่านค่าจากในโมดูล) → ได้เลขจริงสองชุด → คำนวณย้อนกลับหาสูตร → เจอว่า `originX/Y` คือจุดที่ถูก → แก้จุดเดียวจบ

**Session 16 (แผนผิดจากภาพจำ):** AI วางแผน 4 ขั้นสำหรับ 5A โดยขั้น 1–2 คือ "ย้าย logic ถุง/กระเป๋า/สมุด เข้า `PlayerProfile`" และ "ย้ายฟิลด์ตัวละครจาก `Loadout`" — **ทั้งสองอย่างเสร็จแล้วตั้งแต่ S10** ไฟล์สดที่ผู้พัฒนาวางในแชตเดียวกันแสดงว่า `HuntSession.ts` (49 บรรทัด) และ `Pouch.ts` (26 บรรทัด) เป็นเปลือกล้วน ไม่มี logic เหลือ · ผู้พัฒนาอนุมัติ "เริ่มขั้นตอนที่ 1" ไปแล้ว AI จึงตรวจไฟล์ซ้ำก่อนลงมือและพบความจริง → หยุด ไม่ส่งแพตช์เขียนทับของเดิม แล้วเสนอแผนใหม่เหลือ 2 งานเล็ก

**บทเรียน:** ก่อนวางแผนงานรื้อโครงสร้าง **ต้องอ่านไฟล์สดที่ผู้พัฒนาเพิ่งวางก่อนเสมอ** แม้จะอยู่ในแชตเดียวกันแล้วก็ตาม — การมีไฟล์ในมือไม่เท่ากับการอ่านไฟล์

ลำดับความน่าเชื่อถือ:
1. คำบอกผู้พัฒนาในแชต + ไฟล์ที่วางสด (น่าเชื่อถือสุด)
2. **ตัวเลขที่วัดได้จากในเกม/จากหน้าสรุปผล** (แผงวินิจฉัยห้องฝึก · สรุปผล NetSpike)
3. ภาพ Source Control / รายการไฟล์
4. Repomix — ต้องเช็กตัวชี้วัดก่อนใช้

ข้อมูลขัดกัน → ถามผู้พัฒนา **หนึ่งครั้ง** ว่าไฟล์ไหนล่าสุด ห้ามเดาแล้วเขียนซ้ำ

กฎหลัก:
- ออกแบบผู้เล่นเป็นข้อมูล "ต่อคน" · ห้ามเพิ่ม singleton ใหม่ที่ผูกผู้เล่นคนเดียว
- **ข้อมูลผู้เล่นทั้งหมดอยู่ใน `PlayerProfile`** · `loadout` / `huntSession` / `pouch` เป็นเปลือกส่งต่อ `profiles.local` — ห้ามใส่ logic ใหม่ในเปลือก
- **ข้อยกเว้นที่ตั้งใจ (มติ S10 · ยืนยัน S16):** เลเวลเครื่องราง / เลเวลสัตว์ / ดาวตัวละคร ยังเป็นค่ากลางใน `Upgrades.ts` เพราะระบบนี้จะถูกถอดทั้งก้อนหลัง Playtest-1 — ย้ายตอนนี้คือทำสองรอบ · **ไม่ขวางแบบผสม** เพราะมีผู้เล่นท้องถิ่นคนเดียวที่อ่านค่าเหล่านี้
- ปุ่ม/ทิศควบคุมใหม่ผ่าน `getMoveInput()` / `getAttackDir()` / `pollNonMouseInput()` ห้ามอ่าน WASD/เมาส์ตรง
- แยก Scene / Entity / System / Data / UI
- **ตัวเลขสมดุลอยู่ในไฟล์ Data** ไม่กระจายใน Scene
- **ค่าความรู้สึก (ms / ความแรงสั่น / ระยะกล้อง) ห้ามคูณตามขนาดดาเมจ** — ดู 4.17
- **UI ทุกชิ้นวางพิกัดในพื้นที่ออกแบบ 1200×600** ห้ามใช้ขนาดแคนวาส (`cam.width` / `scale.width`) คำนวณตำแหน่ง UI — ดู 4.22
- ตัวเลขอัปเกรด/ดาว → `Upgrades.ts` ที่เดียว UI และเกมต่อสู้อ่านฟังก์ชันเดียวกัน · **ตัวเลขความจุถุง → `data/pouch.ts`** (ใหม่ S16)
- เพิ่มบอสใหม่ → แก้ 3 ไฟล์: `bosses.ts` · `createBoss.ts` · `BossLoader.ts` — ห้ามแตะ `WorldScene.ts` / `AreaBosses.ts`
- เพิ่มมอนสเตอร์เดินสุ่ม → ใช้ `CombatTarget` เดิม ห้ามแก้ `PlayerActor.ts`
- **ท่า/พาสซีฟ/เอฟเฟกต์เฉพาะตัวละครอยู่ใน `src/characters/<Name>Kit.ts`** · `PlayerActor.ts` เป็นของกลางที่ไม่รู้จักชื่อตัวละคร
- ห้าม Backtracking / Chunk Streaming
- `CombatTarget` สร้างครั้งเดียวตอน spawn ห้ามสร้างใน `getTargets()`
- ภาพนิ่ง bake เป็น texture ครั้งเดียว (`textures.exists` กันวาดซ้ำ)
- ทุก Entity มี `destroy()` ที่ไม่ดรอปของ ไม่เรียก `onDeath`
- `DroppedItem` ทุกชิ้นระบุ `source` (`'ground' | 'minion' | 'boss' | 'seal' | 'other'`)
- เสียงใหม่เพิ่มใน `sfx.ts` ที่เดียว ห้ามสร้าง `AudioContext` ที่อื่น
- เงา/แสงใช้ระบบกลาง (`LIGHT` + `makeShadow/syncShadow/makeGlow/destroyGlow`)
- **ห้าม import วนระหว่างโมดูลข้อมูลกับโมดูลระบบ** — บทเรียน S16: `PlayerProfile ↔ Upgrades` วนกันอยู่ตั้งแต่ S10 → แก้โดยแยกค่าคงที่ถุงไป `data/pouch.ts` ให้ทิศเดียว
- กฎสี/แฟลช Phaser 4 → 4.10 · กฎ UI + TS → 4.14 · กฎกล้อง → 4.22

## 4. Current Controls & Systems

### 4.0 โหมดควบคุม 3 แบบ (ใช้งานจริงแล้ว)

สลับด้วย `V` หรือแตะป้ายมุมซ้ายล่าง · จำข้ามรีเฟรช (`arena_controls` แยกจากเซฟเกม) · มือถือเริ่ม touch เดสก์ท็อปเริ่ม mouse

| โหมด | เดิน | ตีเบา / ชาร์จ | สกิล | ทิศตี |
|---|---|---|---|---|
| mouse | WASD | คลิกซ้าย / ค้าง | คลิกขวา | ตามเคอร์เซอร์ |
| keys | WASD / ลูกศร | J / ค้าง J | K | ทิศที่หัน + กรวยช่วยเล็ง (`assistRange`/`assistAngle`) |
| touch | จอยลอยซ้าย | ปุ่มตี / ค้าง | ปุ่มสกิล | เล็งอัตโนมัติ บอสตื่นใกล้สุด → ตัวแทะ 380 → ทิศเดิน |

- ท่า "เล็ง" ไปทางเป้า · ท่า "เคลื่อนที่" (พุ่งของอัคนี) ไปทางที่บังคับอยู่ตอนเริ่มพุ่ง (เฉพาะ keys/touch) ผ่าน `rushDirection()`
- ฐานส่ง `suppressKeyCombat: true` กัน J ชนปุ่มลัด (J = สมุดบันทึก) · `K` dev ตาย ถูกปิดเมื่อโหมด keys
- ปุ่ม E/B/Q/M/R ใช้ได้ทุกโหมด (สัมผัสมีปุ่มบนจอ)

**ใน The World:** E เก็บ/ประตู/ผนึก/เสาฟื้น · B ถุง · Q แผนที่ · R กลับฐานหลังจบ (หรือแตะจอที่หน้าสรุป) · M เสียง
**DEV keys:** N เปลี่ยนแอเรีย · G เติมของ · K ตาย
**ในฐาน:** E ใช้งานจุด · L แต่งตัว · F ตีเหล็ก · B หีบ · J บันทึก · T ออกสำรวจ · 1/2 เปลี่ยนตัวละคร · ENTER ห้องฝึก (DEV เท่านั้น) · F2 แจกของ · F9 ล้างเซฟ

**กฎ Input:** `PlayerActor.onPointerDown` เช็ค `hitTestPointer(p)` ก่อน — UI ใหม่ที่สร้างในฉากต้อง `setInteractive()` ที่พื้นหลังเสมอ กันคลิกทะลุไปออกดาบ

### 4.2 Boss Design Rules

- บอสทุกตัวมีเอกลักษณ์ ห้ามแค่เพิ่ม HP/Damage
- Telegraph บอกพื้นที่/ทิศอันตราย · Rage เปลี่ยนรูปแบบการเล่น
- ระยะอิง `physics.world.bounds` ของแอเรียปัจจุบัน
- เกิดในสภาพ `setSleeping(true)` ตื่นเมื่อเข้าใกล้ `DETECT_RADIUS = 500` ทีละตัว
- ตัวหลับ: ตีไม่ได้ ครกจิ๋วไม่ยิง ไม่ปลุกตัวข้างเคียง
- เลือดใน The World = เลือดฐาน × `hpMult` (ห้องฝึกไม่คูณ) — `def` ถูก clone แล้ว
- ดาเมจขาออกคูณที่ `bossHooks.onHitTarget` จุดเดียวผ่าน `scaleBossDamage()`
- ไฟไหม้คูณที่ `bossHooks.onBurn` ด้วย `burnMult`
- บอสตายใน The World เรียก `huntSession.addBossKill()`
- **(S15) ตอนนี้ `bossHooks.getTargets` คืนผู้เล่นคนเดียว (`[this.actor.sprite]`) — ต้องรองรับหลายคนในช่วง E**
- **(ตรวจแล้ว S16) `BossBase.nearestTarget()` วนลูป `hooks.getTargets()` อยู่แล้ว** → โครงรองรับหลายเป้าพร้อม แค่ฉากส่งรายชื่อเพิ่มใน E · ส่วน hooks ของตัวแทะ (`playerPos` / `playerAlive`) ยังรับคนเดียว ต้องปรับใน E

**บอสที่มี:**
- **ภัสมะ** — ตัวนิ่มลาวา: ไล่ · พ่นไฟกรวยหมุน · พุ่งชน · คลั่งหมุนลูกข่างมีมึนให้ตีกลับ (เลือดฐาน **3000**)
- **มายา** — กระต่ายฝันร้าย: กระโดด · กรงสามเหลี่ยม · หายตัวตุ้ม · แยกร่างปลอม (เลือดฐาน **2600**)

**กฎร่างปลอมมายา:** เหมือนจริงทุกประการ เบาะแสเดียวคือเงาทอดผิดทิศผ่าน `syncShadow(..., isFake = true)` · ตีโดนได้ → แตก + วางสามเหลี่ยมเล็กที่เท้าผู้เล่น (เลือดบอสไม่ลด) · 2 ตัว (คลั่ง 3)

### 4.3 Character Design Rules (ค่าปัจจุบันหลังสเกล ×100)

> ตารางด้านล่างคือ **โค้ดเดิมก่อนรื้อ** — ชุดสกิลใหม่ดู 4.18 และ `docs/design/char/char_akkhani.md`

### 4.4 มอนสเตอร์ + จุดฟื้นเลือด

**ตัวแทะกระดาษ:** สีสันและความเสี่ยงเล็ก ไม่ใช่กำแพง · ตื่นเสมอแต่ไล่เมื่อใกล้ 260 · วงจร เดินสุ่ม → ไล่ → ง้าง 430ms → พุ่ง → นิ่งเปิดให้ตี → กลับบ้านเมื่อห่าง 720 · **เลือด 300 คงที่ทุกเขต** · **ดาเมจ 80** · ตายคายของ 1 ชิ้นเสมอ · ไม่นับเควสเก็บของ · ไม่ปลดประตู

**เสาฟื้นเลือด:** สุ่ม 0–2 จุด · กด E ยืนฟื้น **ทีละ 100 ทุก 600ms** · หยุดเมื่อ ออกนอก 95px / โดนตี / เลือดเต็ม / จบทริป · มีตัวแทะเฝ้า 1 ตัวต่อจุดโดยตั้งใจ

### 4.5 Rarity & Progression

> ⚠️ ระบบดาว / เครื่องราง / เลเวลสัตว์เลี้ยงในหัวข้อนี้คือ **โค้ดตอนนี้ที่มีแผนจะถูกแทนที่** (ดู 4.19) — ยังห้ามลบจนกว่าผู้พัฒนาอนุมัติ

Rarity 4 ระดับ: common (เทา) / rare (ฟ้า) / epic (ม่วง) / legendary (ทอง)

| Item | ใช้กับ |
|---|---|
| Ore | Charm Lv.1–10 + ช่องถุง |
| Wood | Pet Lv.1–10 |
| Bone | ดาวตัวละคร ★0–3 |
| Essence | ฟักไข่ (อนาคต) |

ดรอป: ภัสมะ → Ore + Essence · มายา → Wood + Bone
น้ำหนักฐาน: common 55 / rare 30 / epic 12 / legendary 3 — คูณ `rareBonus` เฉพาะของดี
ทุกทางได้เรทเดียวกัน: ของพื้น · บอส · ตัวแทะ · ของปลอบใจผนึก
วาล์วตำนาน: ผนึกสำเร็จการันตี epic+ 2 ชิ้น · legendary = `0.12 × rareBonus`

ราคาอัปเกรด: [ทั่วไป] 5/10/15 → [หายาก] 3/6/9 → [มหากาพย์] 2/4 → [ตำนาน] 1 + [มหากาพย์] 3
ดาว: ★1 กระดูก[หายาก] 5 · ★2 [มหากาพย์] 3 · ★3 [ตำนาน] 1
หลอม 10→1 ไล่ระดับ

**ผลอัปเกรดหลังสเกล ×100:** ตราต่อชีวิตฟื้น `100 + floor(L/5)×100` · ครกจิ๋ว `200 + floor(L/3)×100` · สกิลอัคนีฟื้น 100 (★3 = 200)

### 4.6 Pouch System

ของในแอเรีย → ถุงพกพา → กลับฐานโอนเข้ากระเป๋าถาวร · 1 ชิ้น = 1 ช่อง · เริ่ม 12 → +4/ขั้น · 12 ขั้น · สูงสุด 60
เต็ม = เก็บเพิ่มไม่ได้ (รวมของเควส) แต่สู้/ไปต่อได้ · ตายเสียครึ่ง (ปัดขึ้น) ไม่มีศพเก็บคืน
**ไม่เซฟ** — ปิดเกมกลางทริป = ของในถุงหาย · แผง B เปิดกลางสนาม เกมไม่หยุดเวลา
**(S16) `pouch` เป็นเปลือกเหนือ `profiles.local`** · **ขั้นถุง (`pouchLevel`) ย้ายเข้า `PlayerProfile` แล้ว** · ตัวเลขความจุอยู่ `data/pouch.ts` · ราคาอัปเกรดยังอยู่ `Upgrades.ts` (`POUCH_COSTS`)
**(S15)** ในโหมดผสมแต่ละเครื่องมีถุงของตัวเอง ส่วนของดรอปที่ host ตัดสินต้องกำหนดว่าใครเก็บได้ (ช่วง E)

### 4.7 ระบบเควส

สุ่มใหม่ทุกแมพ ไม่มีข้ามแอเรีย

| ชนิด | เงื่อนไข |
|---|---|
| collect | เก็บของ `source === 'ground'` ครบ `quest.collectNeed` |
| hunt | ฆ่าบอสหมด (กรองออกถ้าแมพมี 0 บอส) |
| explore | เหยียบจุด 2–3 จุดครบ (ห่างกัน ≥700) |

ประตูไปต่อปลด 2 ทาง: เควสสำเร็จ หรือ ฆ่าบอสหมด · แมพ 0 บอสไม่ปลดฟรี · ประตูกลับฐานเปิดเสมอ

**กฎ Hint (ห้ามละเมิด):** ห้ามลูกศรชี้เป้าเควส (ลูกศรทองชี้ประตูที่ปลดแล้วเท่านั้น) · ใช้ 3 ชั้น: เศษกระดาษโปรยพื้น + แสงวาบเมื่อใกล้ + ข้อความทิศ 8 ทิศ/เมตร/จำนวนที่เหลือ · แผนที่แสดงเฉพาะที่เดินเคยเห็น

**มินิเกมผนึก:** เคอร์เซอร์วิ่งไป-กลับ กด E ในช่องทองครบ 2 แผล พลาดได้ 3 · พลาดแล้วช่องแคบ ×0.75 + สุ่มตำแหน่งใหม่ · เกมไม่หยุด · สำคัญ: ห้ามตั้ง `this.minigame = null` ใน `update()` ให้ callback ตอนจบเคลียร์
**ผนึกพัง:** สะท้อน **100 ดาเมจ** + ของปลอบใจ 1 ชิ้น

### 4.16 สถาปัตยกรรม Co-op ออนไลน์ — "แบบผสม" [ตัดสินใจแล้ว S15]

**ผู้พัฒนาเลือก (S15):** แบบผสม + ทำ 5A (ยอมรื้อโค้ดได้ถ้าจำเป็น) · เป้าหมาย **เล่นกับเพื่อน 2–4 คนในแมพเดียว** · ไม่ต้องกันโกงมาก

**หลักการ 3 ข้อ [ตัดสินใจแล้ว]:**
1. **ตัวละครของแต่ละคน (เดิน ตี ท่า) ให้เครื่องตัวเองคำนวณ** — ไม่หน่วงมือ
2. **บอส ศัตรู ของดรอป ให้เครื่อง host (เพื่อนคนหนึ่ง) เป็นคนตัดสิน** — ทุกคนเห็นบอสตัวเดียวกัน
3. **เพื่อนที่เห็นบนจอ เป็นตัวผี** (`RemotePlayer`) ที่เล่นตามข้อมูลที่ส่งมา — ไม่รันท่าซ้ำ

**ข้อมูลที่ส่ง:**
- client → host: ตำแหน่ง · ทิศ · ชื่อคลิป (+เวลาเริ่ม) · เหตุการณ์ "ฉันตีเป้านี้ ดาเมจเท่านี้" (ท่าใน Kit มี `delayedCall` ซ้อนเยอะ จึงไม่ซิงก์ตัวท่า ซิงก์แค่ผลลัพธ์)
- host → ทุกคน: สแนปช็อตโลก (ผู้เล่นทุกคน + บอส/ตัวแทะ/ของดรอป) ~20 ครั้ง/วินาที
- ทอพอโลยี: **ดาว (star)** — client ต่อกับ host เท่านั้น ไม่ต่อกันเอง (ทดสอบแล้วใน NetSpike)

**อธิบายทางเลือก (สำหรับผู้พัฒนา — S15):**

| | แบบ A เซิร์ฟเวอร์เป็นใหญ่ | แบบผสม (ที่เลือก) |
|---|---|---|
| ใครคำนวณตัวละคร | เซิร์ฟเวอร์คำนวณผู้เล่นทุกคน | แต่ละเครื่องคำนวณตัวเอง |
| ส่งอะไร | ปุ่มที่กด → สถานะทั้งหมด | ตำแหน่ง ทิศ ท่า + เหตุการณ์ตี |
| ความรู้สึกตอนเล่น | ต้องมีระบบเดาล่วงหน้า ไม่งั้นหน่วงเท่าปิง | ตัวเองขยับทันที |
| งานโค้ด | หนักมาก (ตรรกะเกมผูกกับภาพ ต้องรื้อใหญ่) | น้อยกว่า |
| ข้อเสีย | แพงและยาก | โกงได้ (ไม่สำคัญในวงเพื่อน) |

**สถานะหลังปิด 5A (S16):**
- ✅ ข้อมูลผู้เล่นเป็นต่อคนแล้ว (`PlayerProfile` + `ProfileBook`) · `PlayerActor` รับ profile ผ่าน constructor
- ✅ **ฉากอ้าง `this.actor` เดียว = ถูกต้องแล้วสำหรับแบบผสม** — ผู้เล่นจริง 1 ตัวต่อเครื่อง ไม่ต้องรื้อฉากเป็นรายการ actor ตอนนี้ ตัวผีจะเพิ่มเข้ามาเป็นคลาสแยกใน D1/E
- ⏳ ยังไม่ทำ: ตัวผี · ส่งข้อมูลข้ามเน็ต · บอส/ตัวแทะเล็งหลายเป้า · เลือดบอสตามจำนวนผู้เล่น (ยังไม่ตัดสิน) · ลูทแยกต่อคน (ยังไม่ตัดสิน)
- ⏳ **สัตว์เลี้ยงในโหมดผสมยังไม่มีมติ** — host ตัดสินเลือดสัตว์ของทุกคนไหม / บอสเล็งสัตว์เป็นเป้าไหม (ดู 4.27 ข้อค้าง)

**ลำดับงาน [ตัดสินใจแล้ว — ล็อกใน 6.5]:** (1) spike ✅ → (2) 5A ✅ → (3) **ตัวผีในห้องฝึก ← ถัดไป** → (4) ต่อเน็ตจริง (ห้องฝึก → The World → Playtest-1)

### 4.17 สเกลเลือด/ดาเมจ ×100 + กฎค่าความรู้สึก (Session 7 — บังคับ)

**เหตุผล:** เลือดหลักหน่วยทำให้จูนดาเมจบอสไม่ได้ละเอียด — 1 หน่วย = 16.7% ของเลือดอัคนี

**สเกลใหม่: 1 หน่วยเดิม = 100**

| ของ | เดิม | ใหม่ |
|---|---|---|
| อัคนี / ลูมิ HP | 6 / 4 | **600 / 400** |
| ฟันเบาอัคนี | 1 | **100** |
| พุ่งดาบชาร์จ | 2 | **200** |
| สกิลใหญ่ | 3 | **300** |
| ลูมิ ใกล้ / ไกล | 1 / 2 | **100 / 200** |
| ภัสมะ / มายา HP ฐาน | 80 / 70 | **3000 / 2600** |
| ตัวแทะ HP / ดาเมจ | 3 / 1 | **300 / 80** |
| ไฟไหม้ต่อ tick | 1 | **50** |
| เสาฟื้นต่อ tick | 1 | **100** |
| ผนึกสะท้อน | 1 | **100** |

**กฎเหล็กที่เกิดจากบั๊กจริง:**
> **ค่าความรู้สึก (hit-stop ms / ความแรงสั่น / ระยะเด้ง) ห้ามคูณตามขนาดดาเมจตรง ๆ**

**แก้แล้วทั้งสองจุดใน `PlayerActor.ts`:**
```
HIT_STOP_BASE_MS = 40 · HIT_STOP_PER_100 = 12 · HIT_STOP_MAX_MS = 90
SHAKE_BASE = 0.004 · SHAKE_PER_100 = 0.002 · SHAKE_MAX = 0.012
```
ใน `hitTarget`: `weight = min(HIT_STOP_MAX_MS, BASE + (damage/100)*PER_100)` และ `shake = min(SHAKE_MAX, SHAKE_BASE + (damage/100)*SHAKE_PER_100)`

**ข้อควรระวังในท่าใหม่:** ค่า `cam.shake(ms, แรง)` ที่เขียนตรงในท่าของ Kit ต้องเป็นค่าคงที่ ห้ามคูณดาเมจ · เพดานท่าใหญ่ที่ใช้อยู่ ≈ 0.012–0.014 (Ulti B ใช้ 320ms / 0.014)

**ผลข้างเคียงที่รู้:** เลือดหลักร้อยวาดเป็นช่องไม่ได้ → `PlayerHUD` เปลี่ยนเป็นแถบยาว 200px + ขีดแบ่ง 10% + ตัวเลข `600/600`

### 4.22 สถาปัตยกรรมจอ/กล้อง — Session 14 [✅ ปิดแล้ว · ผ่านทั้งคอมและมือถือ]

**หลักคิด [ตัดสินใจแล้ว]: แยก "พื้นที่ออกแบบ" ออกจาก "ความละเอียดวาด"**

| ค่า | ความหมาย | คอม | มือถือ |
|---|---|---:|---:|
| `GAME_WIDTH/HEIGHT` | พื้นที่ตรรกะที่ UI/กล้องยึด **คงที่ทุกอุปกรณ์** | 1200×600 | 1200×600 |
| `CANVAS_W/H` | จำนวนพิกเซลที่วาดจริง | 1834×917 | 2160×1080 |
| `VIEW_SCALE` | `CANVAS_W / GAME_WIDTH` = ตัวคูณซูมทุกกล้อง | 1.528 | 1.800 |

**ผล:** ทุกเครื่องเห็นสนาม 1200×600 เท่ากัน (บาลานซ์การมองเห็นบอสเท่ากัน — ดีต่อ co-op) · ภาพคมตามจอ · UI วางพิกัดเดิมได้

**สูตรคำนวณแคนวาส (`canvasSize()` ใน `config.ts`):**
```
dpr = min(devicePixelRatio, 2)
h   = max(600, min(round(innerHeight × dpr), 1080))
w   = h × 2
```

**`main.ts`:** `width: CANVAS_W` · `height: CANVAS_H` · `pixelArt: false` · `scale: { mode: FIT, autoCenter: CENTER_BOTH }` ทุกอุปกรณ์

#### 🔴 กฎกล้องที่ต้องจำ (พลาดมาแล้ว 5 รอบใน S14)

1. **`setZoom` ขยายโดยยึดกลางช่องมอง** ไม่ใช่มุมซ้ายบน → ถ้าปล่อยไว้ UI จะเยื้องเข้ากลางจอ
2. **วัตถุ `setScrollFactor(0)` ไม่รับ scroll ของกล้อง** → การชดเชยด้วย `setScroll` **ไม่มีผลกับ HUD**
3. **ทางที่ถูกสำหรับกล้อง UI: ตั้ง `originX = 0` / `originY = 0`** แล้ว `setZoom(VIEW_SCALE)`
4. **กล้องโลก (`main`) ไม่ต้องตั้ง origin** เพราะใช้ `startFollow()` ซึ่งคุม scroll เองอยู่แล้ว
5. **ย้ำค่าทุกเฟรม** (`applyRig()` ใน POST_UPDATE / update)
6. **กล้องที่มีวัตถุ scrollFactor 1 แต่อยากให้ตรึงจอ** (เช่น `TouchControlsScene`) → ใช้ rig เดียวกัน แล้ว scroll 0
7. **ห้ามใส่ `centerOn()` โดยไม่ตรวจ typings**

**พิกัดเมาส์/นิ้ว:**
- วัตถุ UI / ปุ่มสัมผัส: `p.x / VIEW_SCALE`
- กล้องโลก (เล็งตี): `cam.scrollX + (p.x − cam.width/2)/cam.zoom + cam.width/2`

### 4.24 ความหน่วงตอนทดสอบ — แยกจาก netcode (S14)

**[ตัดสินใจแล้ว] tunnel ≠ netcode — เป็นสองเรื่องคนละหน้าที่**

| | Cloudflare tunnel + dev server | WebRTC (ช่อง B/D/E) |
|---|---|---|
| หน้าที่ | ส่ง **ไฟล์เกม** จากเครื่องเราไปเพื่อน | ส่ง **ข้อมูลสด** ระหว่างผู้เล่น |
| โปรโตคอล | HTTP (TCP) ผ่านตัวกลาง | UDP-based ต่อตรง (ถ้าต่อติด) |
| เหมาะกับ | โหลดหน้าเว็บครั้งเดียว | ตำแหน่ง/ดาเมจ 30–60 ครั้ง/วิ |

**ทำไม FPS ไม่ตกแต่ยังหน่วง:** `FPS` วัดความเร็ววาดภาพ · dev mode ของ Vite แยกโมดูลเป็นหลายร้อยไฟล์ ทุก `import` คือ 1 HTTP request ผ่านอุโมงค์ → โหลดค้างเป็นช่วง แต่พอโหลดเสร็จ FPS กลับปกติ

**วิธีตัดสิน 3 ขั้น:**
1. หน่วงตอนเปลี่ยนฉาก/เปิดเมนู/โหลดบอส → tunnel+dev server · หน่วงตอนเดิน/ตีต่อเนื่อง → เกมจริง
2. ตัดตัวแปร: `npm run build` แล้ว `npm run preview -- --host` → ถ้าหายหน่วง = ไม่ใช่เกม
3. ยังหน่วงตอนเล่น → F12 Performance จับ spike แล้วส่งผลมา

**[เสนอ — ยังไม่ยืนยัน] สถาปัตยกรรมที่ควรเป็นสำหรับ Playtest:** ไฟล์เกม → host ถาวรฟรี (Cloudflare Pages / GitHub Pages) · ข้อมูลเกม → WebRTC ต่อตรง (PeerJS ห่อ + signaling)

**(S15) วิธีทดสอบมือถือที่ใช้ได้จริง:** `npm run dev -- --host` เปิดผ่านที่อยู่ในวง หรือผ่านอุโมงค์ Cloudflare · **อุโมงค์ต้องตั้ง `server.allowedHosts: ['.trycloudflare.com']` (และ `preview.allowedHosts`) ใน `vite.config.js`** แล้วรีสตาร์ต `npm run dev`

### 4.25 NetSpike — ผลทดสอบการต่อออนไลน์ (Session 15) [✅ ผ่านเงื่อนไขหลัก]

| 3 ผู้เล่น | ✅ (ไม่ได้ส่งตัวเลข) |
| ทิ้งไว้ ~5 นาที | ✅ ไม่หลุด |

**ตัวเลขจากสรุปผล (host · ห้อง LSRW · ผู้เล่น 2 · 584 วินาที):** ต่อแบบ **`srflx <-> srflx`** (ต่อตรง ไม่ผ่าน TURN) · RTT เฉลี่ย **61 ms** · ต่ำสุด 36 · p95 97 · สูงสุด 110 · แกว่ง 15 ms (**แค่ 40 ตัวอย่าง**) · แพ็กเก็ตหาย ~0.1% · ผู้สมัคร ICE host 2 / srflx 2 / relay 0

**ข้อสังเกตที่ยังไม่ยืนยัน (ห้ามนับเป็นข้อสรุป):**
- ส่ง 2,407 / รับ 867 ข้อความใน 584 วินาที ทั้งที่ควรได้ ~11,000 ที่ 20 ครั้ง/วินาที → **สงสัยว่าเบราว์เซอร์หน่วงตัวจับเวลาของหน้าที่อยู่เบื้องหลัง** · **ผลต่อเกม: ถ้า host สลับแอปหรือล็อกจอ บอสอาจค้างให้ทุกคน** · **วิธียืนยัน:** เปิด spike สองเครื่อง ไม่แตะอย่างอื่น ให้หน้าอยู่หน้าสุดตลอด 2 นาที กดสรุป ถ้า "ส่ง" ราว 2,400 ก็คือเดิมไม่ได้พังที่การส่ง
- สรุปของ host ขึ้น `ICE: disconnected` และคู่เส้นทาง 0 คู่ → น่าจะกดสรุปหลังอีกฝั่งออกไปแล้ว · **กดสรุปตอนทั้งสองฝั่งยังใช้งานอยู่**
- **รอบแรกที่ต่อไม่ติดบนไวไฟเดียวกัน:** host เห็นรายการของมือถือ และทั้งสองฝั่งได้ srflx 2 แต่ ICE ไม่ผ่านจน `disconnected` · รอบหลังต่อติดโดยไม่มีสิ่งที่ชี้ได้ว่าเป็นตัวแก้ · **สาเหตุที่เป็นไปได้ (ไม่ยืนยัน):** เร้าเตอร์กันเครื่องในวงเดียวกันคุยกัน · ไฟร์วอลล์ Windows · ชื่อที่อยู่แบบ `.local` · เร้าเตอร์ไม่รองรับการวนผ่านที่อยู่สาธารณะ

**เกณฑ์จบ spike:** ต่อข้ามเครือข่ายจริงได้ ✅ · มีตัวเลขปิงจริง ✅ · รู้ว่าต้องใช้ TURN ไหม 🟨 (คู่นี้ไม่ต้อง · เครือข่ายเพื่อนยังไม่ทดสอบ) · ตัดสินเทคโนโลยี 🟨 [เสนอ]

**[เสนอ] ข้อสรุปเทคโนโลยี:** ใช้ **PeerJS cloud + STUN ต่อตรง** ต่อไป · **TURN เป็นแผนสำรอง** เพิ่มเมื่อเพื่อนคนไหนต่อตรงไม่ติด · **ข้อมูลเดียวที่ปิดความเสี่ยง CGNAT ได้:** ให้เพื่อน 2–3 คนเปิดหน้า spike แล้วกดสรุปผลส่งมา (ทำขนานกับงานอื่นได้) · host ต้องอยู่หน้าจอเกมตลอด

**ข้อมูลบริการที่ตรวจแล้ว (S15 — ห้ามอ้างเกินนี้):**
- **PeerJS cloud:** ทำหน้าที่จับคู่เท่านั้น **ไม่มี TURN ในตัว** · เพดานจำกัด ไม่มีสัญญารับประกัน · ถ้าเพื่อนอยู่หลัง symmetric NAT หรือ CGNAT บางค่า จะต่อไม่ติดถ้าไม่มี TURN
- **TURN ฟรี (Metered Open Relay):** ต้อง **สมัครบัญชี** แล้วรับ URL/username/password จากแดชบอร์ด · โควตาฟรี 20 GB ต่อเดือน (ตามบล็อกของเจ้าของบริการ — **ยังไม่ยืนยันจากหน้าราคาทางการ**) · ก๊อปค่าจากแดชบอร์ดลงช่อง "ตั้งค่า TURN" ของ spike เอง (ห้ามเดาชื่อโฮสต์)
- **ประมาณการปริมาณข้อมูล (คิดเอง ไม่ได้วัด):** ข้อความ ~60–200 ไบต์ × 20 ครั้ง/วินาที ≈ 14 MB ต่อชั่วโมงต่อเพื่อนหนึ่งคน
- **ห้าม:** ฝัง/commit รหัสผ่าน TURN ในโค้ด หรือโชว์ในภาพจับหน้าจอ

**ปัญหาที่เจอระหว่างทาง (บทเรียน):** วาง `main.js` นอก `src` → 404 · Vite "host not allowed" → ตั้ง `allowedHosts` · **host ต้องเปิดผ่านลิงก์อุโมงค์เหมือนกัน** ไม่ใช่ `localhost` · spike รุ่นแรกผูกการดู ICE ไว้หลังเปิดสำเร็จ → ต่อไม่ติดแล้วเงียบ · ปุ่มคัดลอกอัตโนมัติใช้ได้เฉพาะ HTTPS/localhost · Brave มีตั้งค่า WebRTC ที่อาจกระทบ (ยังไม่ยืนยัน)

### 4.26 ระบบสถานะชั่วคราว (Status Modifier) — [ไอเดียใหม่ S16 · ยังไม่มีมติ · ห้ามเขียนโค้ด]

**สิ่งที่ผู้พัฒนาพูดถึง (ยังไม่ใช่ข้อสรุป):**
- พลังโจมตี (เพิ่ม/ลด)
- พลังป้องกัน — ผู้พัฒนาเปิดทางเลือกไว้ว่าอาจเป็น **ระบบเพิ่ม/ลดการรับดาเมจ** หรือ **ตัวคูณ/ตัวหารดาเมจ** แทนค่าป้องกันถาวร
- ความเร็วเคลื่อนที่ (เพิ่ม/ลด)
- ความเร็วการโจมตี (เพิ่ม/ลด)

**ผู้พัฒนาขอให้คิด mechanic core ไว้ด้วย** — แต่ **ยังไม่ได้อนุมัติให้เริ่มทำ** และ **ยังไม่定为ว่าทำก่อนหรือหลังตัวผี**

### 4.27 สัตว์เลี้ยงแบบ有เลือดมีพฤติกรรม — แมวเถ้า (Ash Cat) [ออกแบบแล้ว S16 · ยังไม่มีโค้ด]

**เอกสารฉบับเต็ม:** `docs/design/pets/pet_ashcat.md` (v0.2 · ผู้พัฒนาสร้างไฟล์แล้ว S16)
**สถานะ:** เอกสารออกแบบบนกระดาษ · **การผลิตจริงรอหลัง Playtest-1** · กราฟิกใช้ placeholder ก่อน ([ตัดสินใจแล้ว])

**[ตัดสินใจแล้ว] สิ่งที่ผู้พัฒนากำหนดเอง:**
1. สัตว์เลี้ยงเป็น **ตัวละครตัวหนึ่ง** — มี HP มีค่าสถานะ รับผลบวก/ผลลบได้ (ระบบผลบวกผลลบ = 4.26 ยังไม่มีมติ)
2. มี **การโจมตีปกติอัตโนมัติ** — ผู้เล่นไม่ต้องกดปุ่มสั่งตี
3. **ล้มได้เมื่อ HP หมด** และ **ผู้เล่นเข้าไปฟื้นได้** เหมือนตัวละคร
4. มี **2 ร่างพัฒนา** (ไม่ใช่เลเวล 1–10)
5. เริ่มทำ **1 ตัวก่อน** ค่อยเพิ่มตัวใหม่
6. สัตว์ตระกูล **แมว**
7. ตัวแรกโจมตีได้ **สองระยะ สลับตามเลือดตัวเอง** — เลือดเยอะตีใกล้ · เลือดน้อยหนีไปตีไกล
8. **โหมดใกล้:** ตีปกติฟื้นเลือดตัวเอง · **โหมดไกล:** ไม่ฟื้นเลือดแต่วิ่งเร็วขึ้น
9. **ไม้ตาย:** ถ้าผู้เล่นล้ม สัตว์มาฟื้นได้ **1 ครั้ง**
10. ผู้พัฒนาตั้งข้อสังเกตว่า *"ปกติเล่นคนเดียวล้มคือแพ้ แต่โหมดหลายคนล้มแล้วรอเพื่อนมาฟื้นได้"* → **เป็นกฎใหม่ที่ยังไม่ได้ตัดสิน** (ดูข้อค้าง)
11.want ออกแบบซับซ้อนไว้เลย เพื่อวางระบบเงื่อนไขสำหรับสัตว์ตัวใหม่ในอนาคต

**[เสนอ] สิ่งที่ AI ตั้งให้ (รอยืนยันทั้งหมด):** ชื่อ "แมวเถ้า" / รหัส `ashcat` / ชื่อร่าง "ลูกแมวเถ้า" และ "เสือเถ้า" · ตัวเลขทุกตัว · เกณฑ์สลับโหมด 40/70 (สองเกณฑ์กันสลับรัว) · ตารางลำดับเงื่อนไข 6 แถว · ไม้ตายสละเลือดตัวเอง 50% ฟื้นเจ้าของ 30% · สัตว์ไม่ฟื้นเองต้องให้ผู้เล่นกด E · พาเลตเทาเถ้า/ครีม/ม่วง · รายการคลิป 6 คลิป · placeholder วาดด้วยโค้ด

**สรุปกลไกสำคัญ (รายละเอียดเต็มอยู่ในไฟล์):**

| หัวข้อ | ร่าง 1 | ร่าง 2 |
|---|---:|---:|
| HP | 300 | 450 |
| ดาเมจใกล้ / ไกล | 50 / 40 | 80 / 60 |
| ฟื้นเลือดต่อฮิตใกล้ | 20 | 30 |
| โบนัสความเร็วโหมดถอย | +40% | +50% |
| ความต่างเชิงกลไก | — | ยิงทะลุ 2 ตัว · ไม้ตายให้โล่กัน 1 ฮิต |

**ตารางเงื่อนไข → โหมด (หัวใจของระบบ · [เสนอ]):** อ่านบนลงล่าง แถวแรกที่จริงชนะ
1. เลือดตัวเอง 0 → ล้ม
2. เจ้าของล้ม + ไม้ตายพร้อม + เลือดพอ → ร่ายฟื้นเจ้าของ
3. ห่างเจ้าของเกินระยะหลุด → วิ่งกลับ
4. เลือด ≤ 40% → โหมดถอย (ไกล)
5. เลือด ≥ 70% → โหมดประชิด (ใกล้)
6. เลือด 40–70% → คงโหมดเดิม (กันสลับรัวทุกเฟรม)

**กฎแข็งที่ยึดของเดิม:** สัตว์ห้ามตีเป้าที่หลับอยู่ (ไม่ให้ปลุกบอส) · สัตว์ไม่เก็บของลงถุง

**ข้อค้างที่ต้องตัดสินก่อนเขียนโค้ด (10 ข้อ · อยู่ในไฟล์ข้อ 11):**
1. **เล่นคนเดียวล้ม = จบทริปอยู่ไหม** ← ชนกฎปัจจุบันโดยตรง (ตาย = เสียของครึ่งถุง + จบทริป)
2. ไม้ตาย: สัตว์สละเลือดแล้วอยู่ต่อ หรือล้มทันที
3. ไม้ตาย 1 ครั้งต่อทริป หรือต่อคูลดาวน์
4. เกณฑ์สลับโหมด 40/70 เอาไหม
5. สัตว์ล้มแล้วฟื้นเองได้ไหม
6. บอส/ตัวแทะเล็งสัตว์เป็นเป้าด้วยไหม (กระทบช่วง E)
7. เล่นหลายคน: host ตัดสินเลือดสัตว์ของทุกคนไหม (กระทบแบบผสม)
8. เลเวลสัตว์ 1–10 เดิม → 2 ร่าง เซฟเก่าแปลงอย่างไร
9. วิธีพัฒนาร่าง 2
10. ชื่อ/รหัส/ชื่อสองร่าง เอาไหม

**ผลกระทบต่อโค้ดเมื่อถึงคิว (ยังไม่ทำ):** `data/pets.ts` · `entities/Pet.ts` · `systems/petBehaviors.ts` · `systems/Perks.ts` · `systems/Upgrades.ts` (ถอดเลเวลสัตว์) · `SaveGame.ts` (ย้ายเซฟ) · `GameScene.ts` (สนามทดสอบ) · `WorldScene.ts` (จุดฟื้นสัตว์) · `PlayerActor.ts` (จุดที่ไม้ตายฟื้นผู้เล่น) · [เสนอ] ไฟล์ใหม่ `entities/PetActor.ts` + `systems/petBrain.ts`

**กฎเอกสาร (บทเรียน S16):** pet sheet เก็บเฉพาะข้อมูลของสัตว์ตัวนั้น · **กฎกลางของสัตว์เลี้ยงทุกตัวและแม่แบบการออกแบบต้องอยู่ใน master prompt** ไม่ใช่ปนในไฟล์สัตว์ · ผู้พัฒนาสั่งตัดออกจาก v0.1 แล้วใน v0.2

## 7. AI Workflow Rules

1. หนึ่ง Prompt = หนึ่ง Feature (ยกเว้นสั่ง "ทำเต็มที่/จัดมาเลย")
2. ก่อนแก้โค้ด: แผน 2–4 ประโยค + ไฟล์ที่แก้ + ความเสี่ยง → รออนุมัติ
3. หลังแก้: เช็กลิสต์ทดสอบสั้น ตรวจได้จริง
4. ห้ามลบระบบที่ทำงานได้โดยไม่ตรวจผู้เรียก
5. **ห้ามแก้ Gameplay + Art พร้อมกัน**
6. ห้ามสมมติ Asset มีอยู่ — ตรวจ `public/assets`
7. ใช้ `setTexture()` สำหรับ Animation
8. ห้ามเพิ่ม Library ถ้า Phaser/TS ทำได้
9. ส่งไฟล์เต็ม หรือ "หา/แทนที่ด้วย" ที่ชัด เรียงบนลงล่างพร้อมเลขข้อ
10. **ห้ามอ้างว่าทดสอบแล้วถ้าไม่ได้รันจริง** — ตรวจจากการอ่านโค้ดอย่างเดียวต้องบอกทุกครั้ง สถานะ 🟨 จนผู้เล่นยืนยัน
11. API Phaser 4 ต้องตรวจกับไลบรารีจริง ไม่ใช้ความจำ v3
12. ตรวจ error: F12 Console + `npx tsc --noEmit` · จอดำ = Console + Terminal
13. VS Code Windows Local เท่านั้น
14. Repomix มีอักขระเพี้ยน (`expor t`, `co nst`, `& &`, `= >`, `5 00`) — อ่านข้ามได้ **ห้ามคัดลอกกลับไปเป็นโค้ดจริง**
15. **ก่อนส่งโค้ด กวาดคอมเมนต์หาภาษาอื่นปน** (ละเมิดซ้ำใน S16 — กวาดทั้งข้อความแชตและเอกสารที่ส่ง)
16. ข้อมูลขัดกัน → ถามหนึ่งครั้ง ห้ามเดาเขียนซ้ำ
17. ถ้ารันโค้ดได้: แตกไฟล์จากแพ็ก ใส่แพตช์ รัน `tsc` — ทำไม่ได้ให้บอกตรง ๆ
18. ทุกแพตช์ระบุพาธเต็มจากโฟลเดอร์ที่มี `package.json` + เช็กลิสต์ + ข้อจำกัดที่รู้
19. **ห้ามส่งโค้ดคนละภาษา / ตัวอย่างลอย ๆ ไม่มีที่วาง**
20. **ห้ามเปลี่ยนโครงการออกแบบที่ผู้พัฒนาเลือกไว้แล้ว**
21. **แก้สเกลตัวเลข ต้องกวาดทุกจุดที่คูณตามตัวเลขนั้น**
22. **งานออกแบบ: แยก [ตัดสินใจแล้ว] กับ [เสนอ] เสมอ**
23. **อ้างว่าโค้ดมีกลไกไหน ต้องตรวจจริงก่อน** (บทเรียน S8: `SEAL.pityCount`)
24. **Dash เป็นความสามารถเฉพาะตัวละคร**
25. **ไม่จูน Balance ละเอียดก่อนมีของให้เล่น**
26. **ทำกราฟิกตัวละครให้จบทีละตัว**
27. **(S12) ก่อนส่งแพตช์ที่เรียก `this.p.X()` จาก Kit ต้องเห็นว่า `X` มีอยู่ใน `PlayerActor.ts` จริง**

## 9. Style Guide — Paper Cutout

Art: Paper Cutout / Layered Diorama · Camera: Top-down
Palette: น้ำตาลดิน เขียวมอส เหลืองอำพัน แสงเรืองรอง · Material: กระดาษด้านมีเส้นใย
Light: ซ้ายบน → เงาขวาล่าง ยึด `LIGHT` ที่เดียว · เงาผิดทิศเฉพาะร่างปลอมมายา
เขียว `0x7dff9b` สำเร็จ/ฟื้น · ทอง `0xffd166` เป้า/รางวัล · แดงส้ม `0xff5a3a` อันตราย · ม่วง `0xc084fc` ตัวตน · ฟ้า `0x9de7ff` ทรัพยากร · ครีม `0xe8e0c8` กระดาษ
ฐานอุ่นกว่าสนาม (`BASE_COLOR`) แต่เขียว/ทอง/แดงคงความหมาย
**(ใหม่ S16) สัตว์เลี้ยง/พวก ห้ามใช้แดงส้มหรือทองเป็นสีตัว** — สงวนไว้สื่ออันตรายและรางวัล · แมวเถ้าใช้เทาเถ้า `0x7a736b` + ครีม + ม่วง (ตัวตน) + เทาเข้ม `0x4a4540` [เสนอ]
เสียงโทนกระดาษ/ลม/ไม้ นุ่ม ไม่แหลม · แสงต้องไม่เด่นกว่า Telegraph
**`pixelArt: false` [ตัดสินใจแล้ว S13–S14]** — งานภาพเป็นดินน้ำมัน/กระดาษนุ่ม ไม่ใช่พิกเซลอาร์ตยุค 8-bit

## Do not

- ใช้ Points · Pop-up อัปเกรด/กระเป๋า · Backtracking/Chunk Streaming · ต่อท่อห้อง
- โชว์สูตรคูณในหน้าอัปเกรด · ตัดเควสออกจากแอเรีย
- ใช้ `GAME_WIDTH/HEIGHT` หรือ `WORLD_*` ในแอเรีย (ใช้ `physics.world.bounds`)
- ลูกศรชี้ตรงไปเป้าเควส · เควสข้ามแอเรีย · ของฝากข้ามแมพ · ฟื้นเลือดอัตโนมัติตอนข้ามแมพ
- เปลี่ยน Phaser Version · ลบ Asset เดิม
- แก้ `WorldScene.ts` / `AreaBosses.ts` เพื่อรองรับบอสใหม่
- สร้าง `CombatTarget` ใหม่ทุกเฟรม · สร้างโดยไม่ใส่ `kind`
- เรียก `setTintFill()` · คืนสีหลังแฟลชโดยไม่ `clearTint()`
- เพิ่มตัวนับเควสเก็บของนอก `tryPickup` หรือนับ source ไม่ใช่ ground
- สร้าง `DroppedItem` ไม่ระบุ source
- ตั้ง `this.minigame = null` ตอนจบใน `update()`
- สร้าง `AudioContext` นอก `sfx.ts`
- คำนวณออฟเซตเงาเอง · สร้าง glow ไม่ destroy · glow เหนือ Telegraph
- Container ซ้อน UI · `continue` ใน forEach · พารามิเตอร์ DEPTH ไม่ระบุ `: number`
- RenderTexture / Particle Emitter / add.triangle / static body / `camera.centerOn()` ที่ยังไม่ตรวจ
- อ้างว่า "ยังไม่มีระบบนี้" จากแพ็กเก่า · เขียนโค้ดซ้ำของที่ยืนยันผ่านแล้ว
- **แก้ Gameplay + Balance พร้อม Art**
- เปิดห้องฝึกให้ผู้เล่นจริง
- อ่าน WASD/เมาส์/J-K ตรงใน PlayerActor นอก `getMoveInput`/`getAttackDir`/`pollNonMouseInput`
- `JustDown` ตรงกับ E/M/R ในฉากที่เล่นมือถือ (ใช้ `pressed`)
- ทำ UI สัมผัสนอก `TouchControlsScene.ts`
- เพิ่ม singleton ใหม่ผูกผู้เล่นคนเดียว · **ใส่ logic ใหม่ในเปลือก `loadout`/`huntSession`/`pouch`**
- สัญญาว่า co-op ใช้ได้ทุกเครือข่ายก่อนทดสอบจริง
- สรุปว่า "ทดสอบผ่านแล้ว" จากการคอมไพล์อย่างเดียว
- **คูณค่าความรู้สึก (ms/แรงสั่น) ตามขนาดดาเมจโดยไม่มีเพดาน**
- **ส่งโค้ดคนละภาษากับโปรเจกต์ หรือส่งตัวอย่างไม่มีพาธไม่มีจุดวาง**

## 12. Working Modes

- **Brainstorming** — เสนอ 2–4 แบบ ห้ามส่งโค้ดจนกว่าจะเลือก
- **Update (/update)** — ตรวจสถานะจากไฟล์ล่าสุด แยก Done/Planned ระบุระดับยืนยัน · **ส่งฉบับเต็ม**
- **Build** — วางแผนสั้น ทำทีละ Feature ทดสอบทันที
- **Audit (/audit)** — เทียบเอกสารกับโค้ดจริง รายงานเฉพาะจุดไม่ตรง
- **Design** — ออกแบบบนกระดาษ (Character Sheet / Pet Sheet / ตารางตัวเลข) ไม่แตะโค้ด ไม่แตะภาพ · **เอกสารรายตัวไม่ปนกฎกลาง**
- **Measure (S14)** — อาการภาพไม่ชัด/ต่อเน็ตไม่ติด: เพิ่มบรรทัดวัดก่อน ห้ามส่งแพตช์แก้
- **Explain (S15)** — ผู้พัฒนาบอกว่างง: ยืนยันภาพในหัวผู้พัฒนาก่อน แล้วเทียบด้วยตาราง
- **Sequence (ใหม่ S16)** — ผู้พัฒนาถามว่า "ทำอะไรก่อน": ตอบด้วยลำดับที่ล็อกใน 6.5 + บอกว่าคอนเทนต์ใหม่อยู่ตรงไหน · ถ้าจะเสนอแทรกต้องบอกต้นทุน
