## ⚠️ กฎเหล็กอันดับหนึ่ง — บทเรียนราคาแพง 3 ครั้ง (Session 5 · 7 · 14)

**Session 5:** AI อ่านแพ็กเก่า แล้วสรุปว่า "มินิแมปยังไม่มี · ฐานยังไม่ได้ทำ" ทั้งที่ทำเสร็จแล้ว ผู้พัฒนาต้องแก้ 3 รอบ

**Session 7:** ผู้พัฒนาส่งแพ็กที่ **ยังเป็นก่อนแพตช์สเกลเลือด** (ยังเห็น `maxHP: 6` · `hp: 80` · `DEPTH_TIERS` 1/3/6 · `PlayerHUD` วาดเป็นช่อง) แต่ในแชตยืนยันแล้วว่าวางแพตช์ + `tsc` ผ่าน + เจอบั๊กที่เกิดจากสเกลใหม่เท่านั้น → **ของใหม่กว่าชนะเสมอ ห้ามยึดแพ็กเก่าแล้วเขียนโค้ดทับของที่ทำแล้ว**

**Session 14 (แพงที่สุด — แก้จอทั้งวัน):** AI ส่งแพตช์แก้กล้อง/UI เกิน 8 รอบโดยเดาสาเหตุผิดทุกครั้ง ผู้พัฒนาต้องวางแล้วพังซ้ำ ๆ

ลำดับความผิดพลาดจริงใน S14:
1. เปลี่ยน `width/height` ใน `main.ts` ตามขนาดจอ → พื้นที่ตรรกะเปลี่ยน → UI เพี้ยนทั้งกระดาน (แต่ภาพคมจริง)
2. เดาว่า `makeVignette` ไม่มี `setScrollFactor(0)` ทั้งที่มีครบ → เสียเวลาเปล่า
3. สั่งให้พิมพ์ `game.…` ใน Console ทั้งที่ `const game` อยู่ใน ES module ไม่โผล่เป็น global → `not defined` ทุกคำสั่ง
4. ชดเชย scroll ด้วยเครื่องหมาย **บวก** แทนลบ → เลื่อนหนีไปไกลกว่าเดิม (`เห็น 317` → `เห็น 634`)
5. ลืมว่า **วัตถุ `scrollFactor(0)` ไม่รับ scroll ของกล้อง** → การชดเชย scroll ไม่มีผลกับ HUD เลย (แต่ได้ผลกับปุ่มสัมผัสที่ไม่ได้ตั้ง scrollFactor)
6. ส่งบล็อกอัปเดต master prompt แค่ 200 บรรทัด ทั้งที่เอกสารจริง 1,100 บรรทัด → ผู้พัฒนาต้องแปะฉบับเต็มกลับมาให้

**สิ่งที่ปิดงานได้จริง:** เพิ่มบรรทัดวินิจฉัยในเกม (อ่านค่าจากในโมดูล) → ได้เลขจริงสองชุด → คำนวณย้อนกลับหาสูตร → เจอว่า `originX/Y` คือจุดที่ถูก → แก้จุดเดียวจบ

ลำดับความน่าเชื่อถือ:
1. คำบอกผู้พัฒนาในแชต + ไฟล์ที่วางสด (น่าเชื่อถือสุด)
2. **ตัวเลขที่วัดได้จากในเกม/จากหน้าสรุปผล** (แผงวินิจฉัยห้องฝึก · สรุปผล NetSpike)
3. ภาพ Source Control / รายการไฟล์
4. Repomix — ต้องเช็กตัวชี้วัดก่อนใช้

ข้อมูลขัดกัน → ถามผู้พัฒนา **หนึ่งครั้ง** ว่าไฟล์ไหนล่าสุด ห้ามเดาแล้วเขียนซ้ำ

### 0.1 กฎบังคับงานเอฟเฟกต์ (สรุปจาก skill_effect_integration.md — ใช้เสมอ)

3. **เริ่มทีละ 1 เอฟเฟกต์** ทดสอบผ่านก่อนค่อยเพิ่มตัวถัดไป ห้ามยกทั้งหมวด/ทั้งคลังเข้ามา

7. **ต้องมี fallback** — texture โหลดไม่ได้ เกมต้องเล่นต่อได้ ไม่ crash ไม่ค้างรอ
8. **เก็บเฉพาะไฟล์ที่ใช้จริง** ที่ `public/assets/effects/pixelfx/<หมวด>/<ชื่อ>.png` + `.json` · ห้ามนำ `records/` ทั้งก้อนเข้าเกม · บันทึกที่มาใน `SOURCES.txt`

10. **เอฟเฟกต์ตีโดนแยกต่อตัวละคร** — ใส่ในชุดท่าผ่าน `onHitLanded` ห้ามฝังใน `PlayerActor.hitTarget`
11. **pixelfx เป็นหลัก โค้ดวาดเสริมเฉพาะส่วนที่คลังไม่มี** (ผู้พัฒนาย้ำ S12) — เส้นโค้ง/วงแหวน prototype ที่ซ้อนกับ pixelfx ต้องเอาออก เหลือไว้เป็น fallback เมื่อโหลดภาพไม่ได้เท่านั้น

**ฟอร์แมตรายงานเมื่อทำงานเอฟเฟกต์ (7 หัวข้อ):** เลือก effect + เหตุผล · ตรวจภาพแล้วหรือยัง · วิธีเชื่อม + เหตุผล · ไฟล์ที่แตะ (พาธเต็ม) · ยืนยันไม่แตะ gameplay · ผลทดสอบที่รันจริง · ข้อจำกัด/License

### 4.2 Boss Design Rules

- บอสทุกตัวมีเอกลักษณ์ ห้ามแค่เพิ่ม HP/Damage
- Telegraph บอกพื้นที่/ทิศอันตราย · Rage เปลี่ยนรูปแบบการเล่น
- ระยะอิง `physics.world.bounds` ของแอเรียปัจจุบัน
- เกิดในสภาพ `setSleeping(true)` ตื่นเมื่อเข้าใกล้ `DETECT_RADIUS = 500` ทีละตัว
- ตัวหลับ: ตีไม่ได้ ครกจิ๋วไม่ยิง ไม่ปลุกตัวข้างเคียง
- เลือดใน The World = เลือดฐาน × `hpMult` (ห้องฝึกไม่คูณ) — `def` ถูก clone แล้ว
- ดาเมจขาออกคูณที่ `bossHooks.onHitTarget` จุดเดียวผ่าน `scaleBossDamage()`
- ไฟไหม้คูณที่ `bossHooks.onBurn` ด้วย `burnMult`
- บอสตายใน The World เรียก `huntSession.addBossKill()`
- **(S15) ตอนนี้ `bossHooks.getTargets` คืนผู้เล่นคนเดียว (`[this.actor.sprite]`) — ต้องรองรับหลายคนในช่วง E (ผู้เล่นจริง 1 + ตัวผีของเพื่อน)**

**บอสที่มี:**
- **ภัสมะ** — ตัวนิ่มลาวา: ไล่ · พ่นไฟกรวยหมุน · พุ่งชน · คลั่งหมุนลูกข่างมีมึนให้ตีกลับ (เลือดฐาน **3000**)
- **มายา** — กระต่ายฝันร้าย: กระโดด · กรงสามเหลี่ยม · หายตัวตุ้ม · แยกร่างปลอม (เลือดฐาน **2600**)

**กฎร่างปลอมมายา:** เหมือนจริงทุกประการ เบาะแสเดียวคือเงาทอดผิดทิศผ่าน `syncShadow(..., isFake = true)` · ตีโดนได้ → แตก + วางสามเหลี่ยมเล็กที่เท้าผู้เล่น (เลือดบอสไม่ลด) · 2 ตัว (คลั่ง 3)

### 4.5 Rarity & Progression

> ⚠️ ระบบดาว / เครื่องราง / เลเวลสัตว์เลี้ยงในหัวข้อนี้คือ **โค้ดตอนนี้ที่มีแผนจะถูกแทนที่** (ดู 4.19) — ยังห้ามลบจนกว่าผู้พัฒนาอนุมัติ

Rarity 4 ระดับ: common (เทา) / rare (ฟ้า) / epic (ม่วง) / legendary (ทอง)

| Item | ใช้กับ |
|---|---|
| Ore | Charm Lv.1–10 + ช่องถุง |
| Wood | Pet Lv.1–10 |
| Bone | ดาวตัวละคร ★0–3 |
| Essence | ฟักไข่ (อนาคต) |

ดรอป: ภัสมะ → Ore + Essence · มายา → Wood + Bone
น้ำหนักฐาน: common 55 / rare 30 / epic 12 / legendary 3 — คูณ `rareBonus` เฉพาะของดี
ทุกทางได้เรทเดียวกัน: ของพื้น · บอส · ตัวแทะ · ของปลอบใจผนึก
วาล์วตำนาน: ผนึกสำเร็จการันตี epic+ 2 ชิ้น · legendary = `0.12 × rareBonus`

ราคาอัปเกรด: [ทั่วไป] 5/10/15 → [หายาก] 3/6/9 → [มหากาพย์] 2/4 → [ตำนาน] 1 + [มหากาพย์] 3
ดาว: ★1 กระดูก[หายาก] 5 · ★2 [มหากาพย์] 3 · ★3 [ตำนาน] 1
หลอม 10→1 ไล่ระดับ

**ผลอัปเกรดหลังสเกล ×100:** ตราต่อชีวิตฟื้น `100 + floor(L/5)×100` · ครกจิ๋ว `200 + floor(L/3)×100` · สกิลอัคนีฟื้น 100 (★3 = 200)

### 4.6 Pouch System

ของในแอเรีย → ถุงพกพา → กลับฐานโอนเข้ากระเป๋าถาวร · 1 ชิ้น = 1 ช่อง · เริ่ม 12 → +4/ขั้น · 12 ขั้น · สูงสุด 60
เต็ม = เก็บเพิ่มไม่ได้ (รวมของเควส) แต่สู้/ไปต่อได้ · ตายเสียครึ่ง (ปัดขึ้น) ไม่มีศพเก็บคืน
**ไม่เซฟ** — ปิดเกมกลางทริป = ของในถุงหาย · แผง B เปิดกลางสนาม เกมไม่หยุดเวลา
**(S15)** `pouch` เป็น singleton ของเครื่อง (`systems/Pouch.ts`) — ในโหมดผสมแต่ละเครื่องมีถุงของตัวเอง ส่วนของดรอปที่ host ตัดสินต้องกำหนดว่าใครเก็บได้ (ช่วง E)

### 4.7 ระบบเควส

สุ่มใหม่ทุกแมพ ไม่มีข้ามแอเรีย

| ชนิด | เงื่อนไข |
|---|---|
| collect | เก็บของ `source === 'ground'` ครบ `quest.collectNeed` |
| hunt | ฆ่าบอสหมด (กรองออกถ้าแมพมี 0 บอส) |
| explore | เหยียบจุด 2–3 จุดครบ (ห่างกัน ≥700) |
| seal | แกะผนึกด้วยมินิเกมแถบจังหวะสำเร็จ |

ประตูไปต่อปลด 2 ทาง: เควสสำเร็จ หรือ ฆ่าบอสหมด · แมพ 0 บอสไม่ปลดฟรี · ประตูกลับฐานเปิดเสมอ
ตัวนับ collect เพิ่มที่ `WorldScene.tryPickup()` จุดเดียว และเฉพาะ `source === 'ground'`

**กฎ Hint (ห้ามละเมิด):** ห้ามลูกศรชี้เป้าเควส (ลูกศรทองชี้ประตูที่ปลดแล้วเท่านั้น) · ใช้ 3 ชั้น: เศษกระดาษโปรยพื้น + แสงวาบเมื่อใกล้ + ข้อความทิศ 8 ทิศ/เมตร/จำนวนที่เหลือ · แผนที่แสดงเฉพาะที่เดินเคยเห็น

**มินิเกมผนึก:** เคอร์เซอร์วิ่งไป-กลับ กด E ในช่องทองครบ 2 แผล พลาดได้ 3 · พลาดแล้วช่องแคบ ×0.75 + สุ่มตำแหน่งใหม่ · เกมไม่หยุด · สำคัญ: ห้ามตั้ง `this.minigame = null` ใน `update()` ให้ callback ตอนจบเคลียร์
**ผนึกพัง:** สะท้อน **100 ดาเมจ** + ของปลอบใจ 1 ชิ้น

### 4.9 ระบบเสียง (P1)

Web Audio สังเคราะห์ล้วนใน `sfx.ts` · บัสรวม → คอมเพรสเซอร์ → ลำโพง

### 4.10 กฎสี/แฟลช Phaser 4 (บังคับ)

### 4.12 แผนที่กระดาษ + หมอก + ร่องรอยรัง

เครื่องมือ "รับรู้พื้นที่" ไม่ใช่ลูกศรชี้เป้า — เปิดหมอกด้วยการเดินเท่านั้น

หมอก 3 สถานะ: ไม่เคยเดินทึบ 0.93 / เคยเดินหรี่ 0.42 / ในรัศมี 620 สว่าง · ตาราง 26×20
ร่องรอยเดินทุก 240ms ห่าง ≥55px เก็บ 300 จุด · รังบอสที่พบจำทั้งทริป ตายแล้วขีดฆ่า
ประตูกลับฐานเห็นเสมอ · 3 ขนาด (เต็ม/เล็ก/ปิด) · ไม่เซฟลงเครื่อง · อยู่ `DEPTH.HUD - 1`

**ซูมต่อเนื่อง:** `targetZoom` + `updateCameraZoom(delta)` หน่วง `1 - exp(-delta/260)` · `ZOOM_COMBAT = 0.75 × VIEW_SCALE` / `ZOOM_NORMAL = 1 × VIEW_SCALE` · ตาย/จบทริปบังคับกลับ `ZOOM_NORMAL`

### 4.14 กฎ UI + TypeScript ที่พลาดจริง (บังคับ)

### 4.16 สถาปัตยกรรม Co-op ออนไลน์ — "แบบผสม" [ตัดสินใจแล้ว S15]

**ผู้พัฒนาเลือก (S15):** แบบผสม + ทำ 5A (ยอมรื้อโค้ดได้ถ้าจำเป็น) · เป้าหมาย **เล่นกับเพื่อน 2–4 คนในแมพเดียว** · ไม่ต้องกันโกงมาก

**หลักการ 3 ข้อ [ตัดสินใจแล้ว]:**
1. **ตัวละครของแต่ละคน (เดิน ตี ท่า) ให้เครื่องตัวเองคำนวณ** — ไม่หน่วงมือ
2. **บอส ศัตรู ของดรอป ให้เครื่อง host (เพื่อนคนหนึ่ง) เป็นคนตัดสิน** — ทุกคนเห็นบอสตัวเดียวกัน
3. **เพื่อนที่เห็นบนจอ เป็นตัวผี** (`RemotePlayer`) ที่เล่นตามข้อมูลที่ส่งมา — ไม่รันท่าซ้ำ

**ข้อมูลที่ส่ง:**
- client → host: ตำแหน่ง · ทิศ · ชื่อคลิป (+เวลาเริ่ม) · เหตุการณ์ "ฉันตีเป้านี้ ดาเมจเท่านี้" (ท่าใน Kit มี `delayedCall` ซ้อนเยอะ จึงไม่ซิงก์ตัวท่า ซิงก์แค่ผลลัพธ์)
- host → ทุกคน: สแนปช็อตโลก (ผู้เล่นทุกคน + บอส/ตัวแทะ/ของดรอป) ~20 ครั้ง/วินาที
- ทอพอโลยี: **ดาว (star)** — client ต่อกับ host เท่านั้น ไม่ต่อกันเอง (ทดสอบแล้วใน NetSpike — 4.25)

**อธิบายทางเลือก (สำหรับผู้พัฒนา — S15):**

| | แบบ A เซิร์ฟเวอร์เป็นใหญ่ | แบบผสม (ที่เลือก) |
|---|---|---|
| ใครคำนวณตัวละคร | เซิร์ฟเวอร์คำนวณผู้เล่นทุกคน | แต่ละเครื่องคำนวณตัวเอง |
| ส่งอะไร | ปุ่มที่กด → สถานะทั้งหมด | ตำแหน่ง ทิศ ท่า + เหตุการณ์ตี |
| ความรู้สึกตอนเล่น | ต้องมีระบบเดาล่วงหน้า ไม่งั้นหน่วงเท่าปิง | ตัวเองขยับทันที |
| งานโค้ด | หนักมาก (ตรรกะเกมผูกกับภาพ ต้องรื้อใหญ่) | น้อยกว่า |
| ข้อเสีย | แพงและยาก | โกงได้ (ไม่สำคัญในวงเพื่อน) |

**ต้องแก้ (5A + ช่อง D/E):**
- `PlayerActor` ทำสามหน้าที่ปนกัน (อ่านปุ่มเครื่องนี้ · คำนวณตัวละคร · ใช้ถุง/สถานะทริปของกลาง) → ต้องแยกให้ตัวผีทำงานได้โดยไม่ยุ่งกับปุ่ม/ถุงของเครื่อง
- บอส/ตัวแทะเล็งผู้เล่นหลายคน (ตอนนี้ hooks รับคนเดียว) · เลือดบอสตามจำนวนผู้เล่น (ยังไม่ตัดสิน) · ลูทแยกต่อคน (ใครเก็บได้ — ยังไม่ตัดสิน)
- **ต้องรื้อใน 5A:** `pouch` · `huntSession` · `loadout` · `PlayerActor` · ฉากที่อ้าง `this.actor` เดียว
- ห้องฝึก (4.21) ใช้เป็นสนามทดสอบตัวผีและเน็ตแรกสุด เพราะไม่มี AI/บอส

**ลำดับงาน [ตัดสินใจแล้ว — ล็อกใน 6.5]:** (1) spike (✅ ผลผ่าน) → (2) 5A แยก `PlayerActor` **ห้ามข้ามไปต่อเน็ตในเกมจริงก่อน** → (3) ตัวผีในห้องฝึก → (4) ต่อเน็ตจริง (ห้องฝึก → The World → Playtest-1)

**[เสนอ — ยังไม่ยืนยัน] ลำดับเทคนิคตอนต่อเน็ตจริง:** Tick Rate + Snapshot → Interpolation (ตัวผีใช้ lerp แบบ NetSpike) → (Prediction/Reconciliation เลื่อนไว้ เพราะแบบผสมไม่ต้องใช้)
รายละเอียดใน `docs/ai/skill_netcode_ping.md`

**ความเสี่ยง:** เน็ตมือถือบางเจ้า (CGNAT) อาจต่อไม่ติดถ้าไม่มี TURN (ยังไม่ทดสอบกับเครือข่ายเพื่อนจริง) · บอสเขียนโดยสมมติผู้เล่นเดียว · บั๊กเน็ตเวิร์กดีบั๊กยากมาก · **host สลับแอป/ล็อกจอ = ตัวจับเวลาถูกหน่วง บอสอาจค้างให้ทุกคน (ข้อสงสัยจากตัวเลข NetSpike — 4.25 ยังไม่ยืนยัน)**

**⚠️ ต้องตรวจข้อมูลปัจจุบันก่อนรับรอง (ห้ามอ้างจากความจำ):** เงื่อนไขปัจจุบันของ TURN ฟรี · ข้อจำกัด PeerJS cloud ตอนใช้จริง

### 4.17 สเกลเลือด/ดาเมจ ×100 + กฎค่าความรู้สึก (Session 7 — บังคับ)

**เหตุผล:** เลือดหลักหน่วยทำให้จูนดาเมจบอสไม่ได้ละเอียด — 1 หน่วย = 16.7% ของเลือดอัคนี

**สเกลใหม่: 1 หน่วยเดิม = 100**

| ของ | เดิม | ใหม่ |
|---|---|---|
| อัคนี / ลูมิ HP | 6 / 4 | **600 / 400** |
| ฟันเบาอัคนี | 1 | **100** |
| พุ่งดาบชาร์จ | 2 | **200** |
| สกิลใหญ่ | 3 | **300** |
| ลูมิ ใกล้ / ไกล | 1 / 2 | **100 / 200** |
| ภัสมะ / มายา HP ฐาน | 80 / 70 | **3000 / 2600** |
| ตัวแทะ HP / ดาเมจ | 3 / 1 | **300 / 80** |
| ไฟไหม้ต่อ tick | 1 | **50** |
| เสาฟื้นต่อ tick | 1 | **100** |
| ผนึกสะท้อน | 1 | **100** |

**กฎเหล็กที่เกิดจากบั๊กจริง:**
> **ค่าความรู้สึก (hit-stop ms / ความแรงสั่น / ระยะเด้ง) ห้ามคูณตามขนาดดาเมจตรง ๆ**

**แก้แล้วทั้งสองจุดใน `PlayerActor.ts` (ตรวจจากโค้ดจริง S12):**
```
HIT_STOP_BASE_MS = 40 · HIT_STOP_PER_100 = 12 · HIT_STOP_MAX_MS = 90
SHAKE_BASE = 0.004 · SHAKE_PER_100 = 0.002 · SHAKE_MAX = 0.012
```
ใน `hitTarget`: `weight = min(HIT_STOP_MAX_MS, BASE + (damage/100)*PER_100)` และ `shake = min(SHAKE_MAX, SHAKE_BASE + (damage/100)*SHAKE_PER_100)`

**ข้อควรระวังในท่าใหม่:** ค่า `cam.shake(ms, แรง)` ที่เขียนตรงในท่าของ Kit ต้องเป็นค่าคงที่ ห้ามคูณดาเมจ · เพดานท่าใหญ่ที่ใช้อยู่ ≈ 0.012–0.014 (Ulti B ใช้ 320ms / 0.014)

**ผลข้างเคียงที่รู้:** เลือดหลักร้อยวาดเป็นช่องไม่ได้ → `PlayerHUD` เปลี่ยนเป็นแถบยาว 200px + ขีดแบ่ง 10% + ตัวเลข `600/600`

- ห้ามเปลี่ยนแนวคิดหรือพฤติกรรมหลักของสกิลที่ผู้พัฒนากำหนดไว้เองเพื่ออ้างว่าเป็นการ Balance

- รายละเอียดภายในของบางสกิล เช่น จังหวะ trigger, การใช้พลังสะสม, ทิศทางหรือรูปแบบเลือกเป้าหมาย และปฏิสัมพันธ์กับบอส
- ตัวเลขทุกตัวของสกิล Rework เป็นค่าเริ่มต้นชั่วคราว ไม่ใช่ค่าบาลานซ์สุดท้าย
- จำนวนเฟรม / timing ของแต่ละ Animation ให้กำหนดใน Animation Specification ของตัวละครนั้น

**ความเสี่ยงก่อนเขียนโค้ด:**
1. `PlayerActor.ts` ยังเป็นของกลางที่ใหญ่ — การเพิ่มชุดสกิลใหม่อาจกระทบหลายส่วน

### 4.24 ความหน่วงตอนทดสอบ — แยกจาก netcode (S14)

**[ตัดสินใจแล้ว] tunnel ≠ netcode — เป็นสองเรื่องคนละหน้าที่**

| | Cloudflare tunnel + dev server | WebRTC (ช่อง B/D/E) |
|---|---|---|
| หน้าที่ | ส่ง **ไฟล์เกม** จากเครื่องเราไปเพื่อน | ส่ง **ข้อมูลสด** ระหว่างผู้เล่น |
| โปรโตคอล | HTTP (TCP) ผ่านตัวกลาง | UDP-based ต่อตรง (ถ้าต่อติด) |
| เหมาะกับ | โหลดหน้าเว็บครั้งเดียว | ตำแหน่ง/ดาเมจ 30–60 ครั้ง/วิ |

**ทำไม FPS ไม่ตกแต่ยังหน่วง:** `FPS` วัดความเร็ววาดภาพ ไม่รู้ว่าไฟล์มาช้าหรือเร็ว · dev mode ของ Vite แยกโมดูลเป็นหลายร้อยไฟล์ ทุก `import` คือ 1 HTTP request ผ่านอุโมงค์ → โหลดค้างเป็นช่วง แต่พอโหลดเสร็จ FPS กลับปกติ

**วิธีตัดสิน 3 ขั้น:**
1. หน่วงตอนเปลี่ยนฉาก/เปิดเมนู/โหลดบอส → tunnel+dev server · หน่วงตอนเดิน/ตีต่อเนื่อง → เกมจริง (GC/physics/tween/save)
2. ตัดตัวแปร: `npm run build` แล้ว `npm run preview -- --host` → ถ้าหายหน่วง = ไม่ใช่เกม
3. ยังหน่วงตอนเล่น → F12 Performance จับ spike แล้วส่งผลมา

**[เสนอ — ยังไม่ยืนยัน] สถาปัตยกรรมที่ควรเป็นสำหรับ Playtest:**
- ไฟล์เกม → host ถาวรฟรี (Cloudflare Pages / GitHub Pages) โหลดครั้งเดียว
- ข้อมูลเกม → WebRTC ต่อตรง (PeerJS เป็นตัวห่อ + signaling)
- ผล: ไม่ต้องพึ่ง tunnel ตอนเล่น · ความหน่วงที่เจอตอน dev หายไปเอง

**(S15) วิธีทดสอบมือถือที่ใช้ได้จริง (ยืนยันแล้ว):** `npm run dev -- --host` เปิดผ่านที่อยู่ในวง (`http://192.168.x.x:5173`) หรือผ่านอุโมงค์ Cloudflare · **อุโมงค์ต้องตั้ง `server.allowedHosts: ['.trycloudflare.com']` (และ `preview.allowedHosts`) ใน `vite.config.js` ไม่งั้น Vite ตอบ "host not allowed" แล้วต้องรีสตาร์ต `npm run dev` หลังแก้**

### 4.25 NetSpike — ผลทดสอบการต่อออนไลน์ (Session 15) [✅ ผ่านเงื่อนไขหลัก · 🟨 รอยืนยันปิด]

**โปรเจกต์ทดสอบแยกจากเกม** (ใช้แล้วทิ้ง ไม่แตะ `arena-mvp`): โฟลเดอร์ `netspike/` — `index.html` · `package.json` (`peerjs ^1.5.5` · `vite ^8.3.8`) · `vite.config.js` · `src/main.js` · รัน `npm install` แล้ว `npm run dev` · build ด้วย `npm run build` (ได้โฟลเดอร์ `dist` ใช้ `base: './'` วางที่ไหนก็เปิดได้)

**สิ่งที่ spike ทำ (โครงเดียวกับ 4.16):**
- host สร้างห้อง (รหัส 4 ตัว · peer id `nspk-XXXX`) แล้วส่งลิงก์เชิญ `?room=XXXX` (กรอกรหัสให้ ผู้ใช้กดเข้าห้องเอง เผื่อใส่ TURN ก่อน)
- **ดาว:** client ส่ง `{t:'state', seq, x, y}` และ `{t:'hit', dmg}` ไป host · host ส่ง `{t:'world', seq, players, boss}` ให้ทุกคน 20 ครั้ง/วินาที · ping/pong ทุก 1 วินาที · ห้องเต็ม (4 คน) ตอบ `{t:'full'}`
- host เป็นเจ้าของ "บอส" (วงกลมแดงวนไปมา + เลือด) · ทุกคนเห็นตำแหน่งและเลือดเหมือนกัน · ตัวผีใช้ lerp
- ส่งแบบ `serialization: 'json'` · `reliable: false` · ICE = STUN ของ Google เสมอ + TURN ถ้าผู้ใช้กรอก (มีติ๊ก "บังคับ relay" ไว้พิสูจน์ TURN)
- แผงสถิติ: ชนิดการต่อ (`host`=เครือข่ายเดียวกัน · `srflx`=ต่อตรงผ่าน NAT · `relay`=ผ่าน TURN) · สถานะ ICE · ผู้สมัคร ICE (host/srflx/relay) · RTT เฉลี่ย/ต่ำสุด/p95/สูงสุด/แกว่ง · แพ็กเก็ตหาย · ปุ่ม "สร้างสรุปผลทดสอบ" (ก๊อปส่งได้ · รวมคู่เส้นทาง ICE โดยปิดเลขท้ายที่อยู่)

**ผลทดสอบ (ผู้พัฒนารายงาน):**

| ทดสอบ | ผล |
|---|---|
| คอม ↔ คอมเครื่องเดียวกัน คนละเบราว์เซอร์ | ✅ |
| คอม ↔ มือถือ ไวไฟเดียวกัน ผ่านที่อยู่ในวง (`192.168.1.48:5173`) | ✅ (รอบแรกเคย ❌ ยังอธิบายไม่ได้ — ด้านล่าง) |
| คอม ↔ มือถือ ไวไฟเดียวกัน ผ่านอุโมงค์ Cloudflare | ✅ |
| คอม ↔ มือถือ คนละเครือข่าย ผ่านอุโมงค์ Cloudflare | ✅ |

**ตัวเลขจากสรุปผล (host · ห้อง LSRW · ผู้เล่น 2 · 584 วินาที):** ต่อแบบ **`srflx <-> srflx`** (ต่อตรง ไม่ผ่าน TURN · โหมด STUN อย่างเดียว) · RTT เฉลี่ย **61 ms** · ต่ำสุด 36 · p95 97 · สูงสุด 110 · แกว่ง 15 ms (**แค่ 40 ตัวอย่าง**) · แพ็กเก็ตหาย ~0.1% · ผู้สมัคร ICE host 2 / srflx 2 / relay 0

**ข้อสังเกตที่ยังไม่ยืนยัน (ห้ามนับเป็นข้อสรุป):**
- ส่ง 2,407 / รับ 867 ข้อความใน 584 วินาที ทั้งที่ควรได้ ~11,000 ที่ 20 ครั้ง/วินาที และปิงมีแค่ 40 ตัวอย่างจากที่ควรมีวินาทีละหนึ่ง → **สงสัยว่าเบราว์เซอร์หน่วงตัวจับเวลาของหน้าที่อยู่เบื้องหลัง** (สลับแท็บ/ล็อกจอมือถือ) · **ผลต่อเกม: ถ้า host สลับแอปหรือล็อกจอ บอสอาจค้างให้ทุกคน** · **วิธียืนยัน:** เปิด spike สองเครื่องแล้วไม่แตะอย่างอื่น ให้หน้าอยู่หน้าสุดตลอด 2 นาที กดสรุป ถ้า "ส่ง" ราว 2,400 ก็คือเดิมไม่ได้พังที่การส่ง

- host ต้องอยู่หน้าจอเกมตลอด (ข้อสงสัยเรื่องตัวจับเวลาถูกหน่วงข้างบน) — บอกเพื่อนก่อนเล่น

**ข้อมูลบริการที่ตรวจแล้ว (S15 — ห้ามอ้างเกินนี้):**
- **PeerJS cloud:** ทำหน้าที่จับคู่เท่านั้น **ไม่มี TURN ในตัว** · เพดานจำกัด ไม่มีสัญญารับประกัน · ถ้าเพื่อนอยู่หลัง NAT เข้มงวด (symmetric NAT) หรือเน็ตมือถือแบบ CGNAT บางค่า จะต่อไม่ติดถ้าไม่มี TURN
- **TURN ฟรี (Metered Open Relay):** ต้อง **สมัครบัญชี** แล้วรับ URL/username/password จากแดชบอร์ด · โควตาฟรี 20 GB ต่อเดือน (ตามบล็อกของเจ้าของบริการ — **ยังไม่ยืนยันจากหน้าราคาทางการ**) · แหล่งหนึ่งระบุว่าแบบไม่ต้องสมัครเลิกแล้ว · ก๊อปค่าจากแดชบอร์ดลงช่อง "ตั้งค่า TURN" ของ spike เอง (ห้ามเดาชื่อโฮสต์)
- **ประมาณการปริมาณข้อมูล (ผมคิดเอง ไม่ได้วัด):** ข้อความ ~60–200 ไบต์ × 20 ครั้ง/วินาที ≈ 14 MB ต่อชั่วโมงต่อเพื่อนหนึ่งคน
- **ห้าม:** ฝัง/commit รหัสผ่าน TURN ในโค้ด หรือโชว์ในภาพจับหน้าจอ

**ปัญหาที่เจอระหว่างทาง (เก็บเป็นบทเรียน):**
- วาง `main.js` นอกโฟลเดอร์ `src` → หน้าเว็บ 404 `/src/main.js` (หน้าว่าง ข้อความ "ยังไม่ได้เชื่อมต่อ" ไม่เปลี่ยน)
- Vite ตอบ "host not allowed" เมื่อเปิดผ่านอุโมงค์ → ตั้ง `allowedHosts` (4.24)
- **host ต้องเปิดผ่านลิงก์อุโมงค์เหมือนกัน** ไม่ใช่ `localhost` ไม่งั้นลิงก์เชิญที่สร้างให้ใช้ไม่ได้ (หรือส่งแค่รหัส 4 ตัว)
- spike รุ่นแรกผูกการดู ICE ไว้หลังเปิดสำเร็จ → ต่อไม่ติดแล้วเงียบสนิท → แก้ให้บันทึกตั้งแต่เริ่มต่อ (กฎ 📏)
- ปุ่มคัดลอกอัตโนมัติใช้ได้เฉพาะ HTTPS/localhost (มีกล่องข้อความสำรองให้ก๊อปเอง)
- Brave มีตั้งค่า WebRTC ที่อาจกระทบการต่อ (**ยังไม่ยืนยัน**) — ถ้าต่อไม่ติดเฉพาะ Brave ให้ลอง Chrome เทียบ

**วิธีทดสอบซ้ำหรือกับเพื่อน:** เปิดหน้า spike → host กด "สร้างห้อง" (เปิดผ่านลิงก์ที่เพื่อนเข้าได้) → เพื่อนเปิดลิงก์เชิญ กด "เข้าห้อง" → ตีบอสสลับกัน ทิ้งไว้ ≥ 2 นาทีโดยหน้าอยู่หน้าสุด → ทุกคนกด "สร้างสรุปผลทดสอบ" แล้วก๊อปส่ง · อ่าน: `ต่อแบบ` + ปิง + แพ็กเก็ตหาย + จำนวน "ส่ง/รับ" เทียบ ~20 ต่อวินาที

### 6.5 ROADMAP สู่ Playtest-1 (Multiplayer)

**ที่มา:** ผู้พัฒนารู้สึกว่าเกม "ไม่ค่อยไปไหน" และไม่รู้ว่าแค่ไหนถึงจะพอ → วางเส้นทางพร้อมเกณฑ์จบของแต่ละช่วง
**สถานะข้อมูล:** [ตัดสินใจแล้ว] = ผู้พัฒนาสั่ง · [เสนอ] = AI เสนอ **ต้องยืนยันกับผู้พัฒนาตอนเริ่มแต่ละช่วง** ห้ามเขียนโค้ดตามข้อ [เสนอ] ที่ยังไม่ได้ยืนยัน

**[ตัดสินใจแล้ว]**
- เป้าหมายใกล้สุด = ไปให้ถึงจุดทดลองเล่น multiplayer
- ทำให้รองรับมือถือก่อน และเปลี่ยนจอเป็นแนวนอน (งานแรก — **ปิดแล้ว S14**)

- อนุมัติ 4 ข้อ (ตอบ "ตามนั้น" 2026-11-23): Playtest-1 ตัดสัตว์/ฟาร์ม/ความก้าวหน้า (ปลดสกิลครบ) · เน็ตแบบผ่อนอำนาจ · ทำ spike ก่อน 5A · เลือกขนาดจอใหม่

## 7. AI Workflow Rules

1. หนึ่ง Prompt = หนึ่ง Feature (ยกเว้นสั่ง "ทำเต็มที่/จัดมาเลย")
2. ก่อนแก้โค้ด: แผน 2–4 ประโยค + ไฟล์ที่แก้ + ความเสี่ยง → รออนุมัติ
3. หลังแก้: เช็กลิสต์ทดสอบสั้น ตรวจได้จริง
4. ห้ามลบระบบที่ทำงานได้โดยไม่ตรวจผู้เรียก
5. **ห้ามแก้ Gameplay + Art พร้อมกัน**
6. ห้ามสมมติ Asset มีอยู่ — ตรวจ `public/assets`
7. ใช้ `setTexture()` สำหรับ Animation
8. ห้ามเพิ่ม Library ถ้า Phaser/TS ทำได้
9. ส่งไฟล์เต็ม หรือ "หา/แทนที่ด้วย" ที่ชัด เรียงบนลงล่างพร้อมเลขข้อ
10. **ห้ามอ้างว่าทดสอบแล้วถ้าไม่ได้รันจริง** — ตรวจจากการอ่านโค้ดอย่างเดียวต้องบอกทุกครั้ง สถานะ 🟨 จนผู้เล่นยืนยัน
11. API Phaser 4 ต้องตรวจกับไลบรารีจริง ไม่ใช้ความจำ v3
12. ตรวจ error: F12 Console + `npx tsc --noEmit` · จอดำ = Console + Terminal
13. VS Code Windows Local เท่านั้น
14. Repomix มีอักขระเพี้ยน (`expor t`, `co nst`, `& &`, `= >`, `5 00`) — อ่านข้ามได้ **ห้ามคัดลอกกลับไปเป็นโค้ดจริง**
15. **ก่อนส่งโค้ด กวาดคอมเมนต์หาภาษาอื่นปน**
16. ข้อมูลขัดกัน → ถามหนึ่งครั้ง ห้ามเดาเขียนซ้ำ
17. ถ้ารันโค้ดได้: แตกไฟล์จากแพ็ก ใส่แพตช์ รัน `tsc` (และ `vite build` ถ้าแตะ main/index) — ทำไม่ได้ให้บอกตรง ๆ
18. ทุกแพตช์ระบุพาธเต็มจากโฟลเดอร์ที่มี `package.json` + เช็กลิสต์ + ข้อจำกัดที่รู้
19. **ห้ามส่งโค้ดคนละภาษา / ตัวอย่างลอย ๆ ไม่มีที่วาง**
20. **ห้ามเปลี่ยนโครงการออกแบบที่ผู้พัฒนาเลือกไว้แล้ว** — เสนอได้ ตัดสินเป็นผู้พัฒนา
21. **แก้สเกลตัวเลข ต้องกวาดทุกจุดที่คูณตามตัวเลขนั้น** (บทเรียน hitStop และ cam.shake)
22. **งานออกแบบ: แยก [ตัดสินใจแล้ว] กับ [เสนอ] เสมอ**
23. **อ้างว่าโค้ดมีกลไกไหน ต้องตรวจจริงก่อน** (บทเรียน S8: `SEAL.pityCount`)
24. **Dash เป็นความสามารถเฉพาะตัวละคร** — ห้ามถือเป็นความสามารถพื้นฐาน/กลาง
25. **ไม่จูน Balance ละเอียดก่อนมีของให้เล่น**
26. **ทำกราฟิกตัวละครให้จบทีละตัว**
27. **(S12) ก่อนส่งแพตช์ที่เรียก `this.p.X()` จาก Kit ต้องเห็นว่า `X` มีอยู่ใน `PlayerActor.ts` จริง** — ถ้าไม่เห็นไฟล์ ให้ขอไฟล์ก่อน ห้ามเดา · ถ้าต้องสร้างเมธอดใหม่ ให้บอกชัดว่าเป็นของใหม่

## 9. Style Guide — Paper Cutout

Art: Paper Cutout / Layered Diorama · Camera: Top-down
Palette: น้ำตาลดิน เขียวมอส เหลืองอำพัน แสงเรืองรอง · Material: กระดาษด้านมีเส้นใย
Light: ซ้ายบน → เงาขวาล่าง ยึด `LIGHT` ที่เดียว · เงาผิดทิศเฉพาะร่างปลอมมายา
เขียว `0x7dff9b` สำเร็จ/ฟื้น · ทอง `0xffd166` เป้า/รางวัล · แดงส้ม `0xff5a3a` อันตราย · ม่วง `0xc084fc` ตัวตน · ฟ้า `0x9de7ff` ทรัพยากร · ครีม `0xe8e0c8` กระดาษ
ฐานอุ่นกว่าสนาม (`BASE_COLOR`) แต่เขียว/ทอง/แดงคงความหมาย
เสียงโทนกระดาษ/ลม/ไม้ นุ่ม ไม่แหลม · แสงต้องไม่เด่นกว่า Telegraph
**`pixelArt: false` [ตัดสินใจแล้ว S13–S14]** — งานภาพเป็นดินน้ำมัน/กระดาษนุ่ม ไม่ใช่พิกเซลอาร์ตยุค 8-bit · ผู้พัฒนาเทสแล้วชอบกว่า

## Do not

- ใช้ Points · Pop-up อัปเกรด/กระเป๋า · Backtracking/Chunk Streaming · ต่อท่อห้อง
- โชว์สูตรคูณในหน้าอัปเกรด · ตัดเควสออกจากแอเรีย
- ใช้ `GAME_WIDTH/HEIGHT` หรือ `WORLD_*` ในแอเรีย (ใช้ `physics.world.bounds`)
- ลูกศรชี้ตรงไปเป้าเควส · เควสข้ามแอเรีย · ของฝากข้ามแมพ · ฟื้นเลือดอัตโนมัติตอนข้ามแมพ
- เปลี่ยน Phaser Version · ลบ Asset เดิม
- แก้ `WorldScene.ts` / `AreaBosses.ts` เพื่อรองรับบอสใหม่
- สร้าง `CombatTarget` ใหม่ทุกเฟรม · สร้างโดยไม่ใส่ `kind`
- เรียก `setTintFill()` · คืนสีหลังแฟลชโดยไม่ `clearTint()`
- เพิ่มตัวนับเควสเก็บของนอก `tryPickup` หรือนับ source ไม่ใช่ ground
- สร้าง `DroppedItem` ไม่ระบุ source
- ตั้ง `this.minigame = null` ตอนจบใน `update()`
- สร้าง `AudioContext` นอก `sfx.ts`
- คำนวณออฟเซตเงาเอง · สร้าง glow ไม่ destroy · glow เหนือ Telegraph
- Container ซ้อน UI · `continue` ใน forEach · พารามิเตอร์ DEPTH ไม่ระบุ `: number`
- RenderTexture / Particle Emitter / add.triangle / static body / `camera.centerOn()` ที่ยังไม่ตรวจ
- อ้างว่า "ยังไม่มีระบบนี้" จากแพ็กเก่า · เขียนโค้ดซ้ำของที่ยืนยันผ่านแล้ว
- **แก้ Gameplay + Balance พร้อม Art**
- เปิดห้องฝึกให้ผู้เล่นจริง
- อ่าน WASD/เมาส์/J-K ตรงใน PlayerActor นอก `getMoveInput`/`getAttackDir`/`pollNonMouseInput`

- ทำ UI สัมผัสนอก `TouchControlsScene.ts`
- เพิ่ม singleton ใหม่ผูกผู้เล่นคนเดียว
- เริ่ม netcode ในเกมจริงก่อนปิด 5A · สัญญาว่า co-op ใช้ได้ทุกเครือข่ายก่อนทดสอบจริง
- สรุปว่า "ทดสอบผ่านแล้ว" จากการคอมไพล์อย่างเดียว
- **คูณค่าความรู้สึก (ms/แรงสั่น) ตามขนาดดาเมจโดยไม่มีเพดาน** (รวมค่า `cam.shake` ที่เขียนตรงในท่าของ Kit)

## 12. Working Modes

- **Brainstorming** — เสนอ 2–4 แบบ ห้ามส่งโค้ดจนกว่าจะเลือก
- **Update (/update)** — ตรวจสถานะจากไฟล์ล่าสุด แยก Done/Planned ระบุระดับยืนยัน · **ส่งฉบับเต็ม**
- **Build** — วางแผนสั้น ทำทีละ Feature ทดสอบทันที
- **Audit (/audit)** — เทียบเอกสารกับโค้ดจริง รายงานเฉพาะจุดไม่ตรง
- **Design** — ออกแบบบนกระดาษ (Character Sheet / ตารางตัวเลข) ไม่แตะโค้ด ไม่แตะภาพ
- **Measure (S14)** — อาการภาพไม่ชัด/ต่อเน็ตไม่ติด: เพิ่มบรรทัดวัดก่อน ห้ามส่งแพตช์แก้
- **Explain (ใหม่ S15)** — ผู้พัฒนาบอกว่างง: ยืนยันภาพในหัวผู้พัฒนาก่อน แล้วเทียบด้วยตาราง
